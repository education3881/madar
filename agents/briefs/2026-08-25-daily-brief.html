The check that had never been checked

Yesterday's work is still sitting in the working tree — produced, briefed, never committed. This push carries two days. And it is fortunate it does, because yesterday's fail-loud guard would have broken the deploy on its first push. Then the lens moved to the reader I said I had never asked about, and the answer took three attempts to measure honestly. Zambia is written.

Yesterday

A full day's work that never left the machine

2026·08·24 · produced · not pushed
State — a push gap, and I want to name it precisely
Not a dark day. 08-24 ran and delivered: the og:locale, og:type and og:site_name fixes, the print stylesheet, the git lastmod resolver, a new standing assertion, guidebook row 27, the Zambia commission and Brief 56. None of it was ever committed. Origin and local both sit at 5e16db2 — the 08-23 commit — while the working tree carries an entire day.
Nothing lost, nothing live stale. But yesterday's brief closed with “no push gap,” which was true of 08-23 and became untrue overnight. Third instance of the push race, in its quietest form: not a push landing mid-run, but a block staged and never taken.
Why it matters more than usual this time
The gap bought us a day, and the day was needed. Two of the things sitting unpushed were wrong in ways that would only have shown up in the deploy — see below. Had 08-24 landed on schedule, the site would have gone red last night and I would be writing a different brief. I would still rather have the push than the luck.
Today

Three wrong numbers before the right one

2026·08·25 · Brief 57 · QA green · ruling #35
Quality — yesterday's guard would have broken the deploy
The lastmod resolver I shipped yesterday was written specifically to fail loudly rather than emit an empty sitemap in CI. It uses the pathspec web/src. A git pathspec resolves relative to the current directory, and the workflow sets working-directory: web — where web/src matches nothing, git exits 0, the map comes back empty, and the resolver's own empty-map guard fails the build.

So the guard written to prevent a silent CI failure would have caused a loud one, on the first push carrying it. That is ruling #16 — verify in the judging environment — biting the very file whose comment block cites ruling #16. Fixed with :/web/src, git's repo-root-relative pathspec, which resolves identically from any directory.
Verified the way it should have been yesterday: built with CI=true inside a real non-shallow clone. 82 URLs, 82 lastmod. A second defect in the same file: it treated “shallow repo” and “no repo at all” as one failure, which made the site unbuildable outside a git tree. Wrong data and missing data deserve different answers.
Quality — the reader I said I had never asked about
A screen reader takes its voice from the nearest lang in the accessibility tree. It never looks at the script of the characters. So Arabic text sitting under lang="en" is not read with an accent — it is read as noise.

471 chrome strings, live for 92 days. The language switcher on every page in both directions, because hreflang describes the destination document and says nothing about the language of the link text. The Latin half of the wordmark, whose Arabic twin has carried lang="ar" since the site was built. Forty RSS. And the share strip, where every aria-label had been carefully localised and the three captions a person actually sees had not — the usual oversight, exactly backwards.

The one I mind: Skip to content, in English, on all 40 Arabic pages. Not a markup defect — an untranslated string, and the first thing a screen reader announces on every Arabic page we have ever published.
471 → 0, across the same 3,230 checked nodes. The still colophon needed a different fix from the rest: سكون · The Still · Curated NN is genuinely bilingual inside one span, and lang describes a run of text, not a box — so it is now split into script runs rather than labelled wholesale.
Research — ruling #35, and it is about my own work
An assertion must be proved against a known-good control, not only against the bug.

Ruling #16 says prove a new check fails on the defect it was written for. I have been treating that as the whole proof. It is half. A check pointed only at broken output cannot distinguish I found the bug from I flag everything — both produce a number, and both produce a satisfying red.

I know because it happened three times in an hour. My first version reported 40 defects and had no model of inheritance — the exact mechanism it was auditing. My second reported 542 and flagged مدار on the editions page: the wordmark, correctly marked since launch, the one place on this site where somebody had already solved this exact problem. That is the control, and it failed. My third reported 473, then 471, after I stopped excluding article prose by guessing at a class name — a guess that had been reporting the name Elsevier and a Spanish pull-quote as defects.
Crying wolf on correct copy is how a standing assertion gets ignored, which is worse than not having one. Corollary now binding: the first number a new assertion reports is not a finding, it is a hypothesis about the assertion. Both of today's new checks ship with both proofs recorded — the count on the broken build, and a named control they did not fire on.
Growth — a sitemap entry is a declaration, a link is an edge
VALENCE has been published since 8 August. It returns 200, every link on it resolves, and it sits in the sitemap — which is why the 08-18 sweep recorded the orphan as cleared. Nothing on this site links to it. Nothing ever has. For 17 days it has been reachable only by someone who already knew the URL.

Our sweeps have always asked does this link resolve and is this page in the sitemap. Neither asks the question a crawler actually answers: starting at the front door and following links, where can I get to? I ran it. 81 of 82.

This matters more than it would have last month. With 0 of 82 URLs indexed, the first crawler to arrive will walk the graph — and anything off the graph stays invisible even after the rest starts working. Fixed: VALENCE now has a home on the editions index under Standing pieces.
82 pages · 82 reachable · 0 orphans. Click-depth from the home page: 1 / 11 / 40 / 30. Now a standing check, so the next orphan is caught the day it appears rather than seventeen days later.
Content — the first Edition 05 draft is written
The law that moved the finish line — roughly 2,270 words, held at approved: false.

Zambia's Act turns on a fourteen-word sentence: “A child who is a citizen shall have the right to free education.” Not a programme, not an appropriation — a right that now has to be repealed in Parliament rather than ended by memorandum. The piece reads the instrument rather than the coverage of it, which is where the four clauses nobody reported are: the citizenship gate, the three-year criminal penalty for aiding a non-citizen child, accommodation brought inside the fee ban and defined down to the mattress, and an undefined ministerial carve-out that is where any future re-charging will happen.

And the thing that is not in any coverage at all: the same Act moved the end of primary school from Grade 7 to Grade 6 — the boundary Zambia's headline access statistic has been measured on for twenty years. The 2002 policy abolished fees “for grades 1 to 7”; the 2026 Act redefines primary as 1–6. The series does not become false. It becomes discontinuous, and the moment to say so is before the first post-Act figures are published rather than after.
All nine standing prohibitions honoured: no “children returned” aggregate — and it is declined inside the piece, citing the Ministry's own record of a two-year bulletin lag rather than our suspicion; no ESB figures; no Act number; the teacher table given as line items, then printed total, then the statement that they do not reconcile while the other three columns do. The August election is named, not tiptoed around.
Content — and the build caught me
The dek came in at 232 characters against a 200 cap and the build refused it before any human read a word. Trimmed to 177 in the same run. Same shape as the England Arabic dek on 08-08.

Worth one line for the record, because it surprised me: a held piece still validates against the schema. approved: false filters the route; it does not bypass validation. That is the correct design, and today it did its job.

Quality — the half of accessibility I have not touched
Today answered the language question. It did not answer the keyboard question, which is the other half of the same surface and the one I cannot check by reading rendered HTML: is the share rail reachable and, more importantly, escapable by keyboard; is focus visible against a paper-cream ground at every interactive element; does the copy-link button announce that it copied to someone who cannot see the toast; and do the Stills' long descriptive alt texts read as illustration or as an obstacle to a reader who has to hear all of them before reaching the prose. That last one is a genuine editorial question rather than a technical one, and I would like the Designer's view before I change anything.
Waiting on you — still two, and the first is now cheaper than it will ever be again
The custom domain. The argument from yesterday is stronger today, not weaker. Nothing has been crawled, so there is no index to confuse — but every day adds URLs carrying canonical tags, hreflang pairs, structured-data identifiers and, as of this push, 82 lastmod values that would all need reissuing. Doing it before a crawler arrives is nearly free. Doing it after is asking an index to forget and relearn.

Substack. One issue sent is an inbound link, a referral path and a return-rate measurement in a single action. Until it exists, Growth is preparation rather than operation — and today's work is a good illustration: the link graph is now complete and correct, and there is still nothing pointing into it from outside.
Standing offer, unchanged: if the domain answer is “not yet” and you want a crawl regardless, IndexNow needs a key file and one POST. I do not make network writes on my own. Say the word and the Web Developer prepares it.
