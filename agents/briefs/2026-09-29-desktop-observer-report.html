Research-to-learn · two increments, both about this operation’s wiring
A concurrency group binds only the runners inside it. madar-weekly.yml shares the madar-autonomous-run group with the daily run on purpose — its own comment cites the 2026-08-23 near-clobber of the guidebook index as the reason. That closed two-agents-one-index for both runners in GitHub Actions. A third runner on a different surface cannot be serialised by that group at all; it can only be retired. The corollary is the one that cost fifteen days: a cadence is not a runner. The 09-14 migration retired the desktop cadence written in the repository and had no reach over the schedule written outside it.
Second: --log is a write. The brief template instructs every run to call madar_stats.py --log, which appends a dated snapshot to history.jsonl. Called by a second runner on the same date, that is a duplicate row in the one series built for deltas. This run called the script without --log. The ruling: any instruction that appends to a shared series must name which runner owns the append — an instruction that mutates shared state is not safely reissued to a second executor.
