Manager → Founder

The same commit, built twice, publishes the magazine in a different order.

Fixing yesterday’s red deploy meant asking a plain question: is the feed we serve the feed we built? So we took today’s build and compared it, file by file, against the live site — at the exact commit today’s build was made from. The two should have been identical.

Five pages and both feeds were different. Same pieces, same byte counts, same everything — in a different order. The cause is one line, repeated eight times: we sort pieces by date, and we never said what to do when two pieces share a date. Sixteen of our pieces share 7 July. Twenty-four of thirty-eight are in a tie with something. For those, the running order of the publication has never been a decision anyone made — it was whatever order the operating system happened to hand us the files in, which can differ between two machines, and did.

We have nine automated checks reading those exact pages every build. Not one of them could ever have caught this, and every one of them was right. They all ask the same kind of question: is everything present? A set has no order. Yesterday’s ruling said two sets of the same size are not the same set. Today’s says the same set, twice, is not the same page.

And because the feeds were on the desk anyway, we finally asked the question that has been written down and unanswered since 18 August: what does a feed reader actually receive? It bit immediately. Every share card in both feeds — seventy-six of them — has been advertised to readers as an empty file since the day we shipped them.

Today

A comparator that returns zero is a decision delegated

Sunday 20 September 2026 · brief 79
Quality · the finding, and how it was reached
Not by looking for it. The red deploy put both feeds on the desk, and checking them meant comparing what we build against what is served. 115 of 120 pages matched. Five did not, and neither did either feed.

We sort every list on the site — both home pages, both editions pages, every browse page, both feeds — newest first. When two pieces share a date, the sort says nothing, so the tie falls back to the order the files came off disk. That is not random, which is what made it invisible: it is perfectly repeatable on any one machine, and can differ between two. Our build was not a function of its sources.
The detail worth keeping: one of our nine sort sites already did it correctly — in a file the other eight import from. The right shape was in the codebase the whole time and was never carried across, and nothing asked.
Quality · standing check 20, and the test we refused to use
One shared comparator now orders every list, and a twentieth standing check asserts that what the site serves is in that order.

The obvious test would be “build it twice and compare.” We rejected it, on evidence rather than taste: two builds on the same machine share a disk order, so that test passes for a reason unrelated to the thing it claims to check. We measured it — two consecutive builds here are byte-identical, on a tree whose sorting we had just proved defective. That test would have certified the bug as fixed.
Proved eight ways before landing, including rebuilding the actual historical defect and confirming the build genuinely fails. Two of our own false alarms during construction are written into the file rather than quietly deleted — the first draft broke on a legitimate tie that spans two editions, the second flagged 76 correct pages because it judged our hand-picked “related reading” lists by date when their order is editorial. Each list is now judged against the order its own source declares.
Growth · the feeds, owed since 18 August, and they were lying
Every item in both feeds carries its share card as an attachment, and every attachment declares how many bytes it is. Ours all declared zero. Seventy-six of them, both languages, every piece, since the day attachments shipped. The images themselves are fine — real, valid, 1–20 KB, correctly typed. We were telling every feed reader they were empty, which is the one field a reader consults before deciding whether to fetch the picture at all.
This is the August defect one surface over, and the same lesson: the file existed, the address resolved, every check we own passed — because every check we own asks does it resolve. Fixed, and gated by standing check 21. No traffic claim attaches to this: we carry no tracker by design, so we can say what the bytes permitted and not what any reader did.

Knowledge
Ruling #58 — a comparator that returns zero is a decision delegated. With two corollaries earned within the hour: a stable sort does not make a partial order total, and order is a property of a list, not of a page. Seventh member of the family that began in August with a green check is scoped to what it enumerates — and the first whose missing enumeration is not a set at all.

Quality · the surface owed for the fourth time

Today that stopped being a design question. Diagnosing the red deploy required writing exactly that comparison, and it found ruling #58 on its first run — while the standing tool whose entire job is drift reported clean at the same moment, because it compares dates and four sample pages and can see neither. The instrument exists. It is in a temporary file. Tomorrow it becomes a standing check.
