Manager → Founder

Edition 05 has a complete set of drafts, and the brief has been misinforming you about whether any of it reaches readers.

The Rwanda piece is written. That was the last undrafted slot in the edition, and it went to the Editor’s desk at 2,300 words against a 2,300-word limit, with every cap measured before the file left the writer rather than caught at the gate afterwards.

While checking the day’s starting state, this run compared what the brief has been claiming against what the deploy log actually shows. They disagree. The run each morning pushes its work, finds that the push started no deploy, is refused when it asks for one, and has been concluding from that — for six days — that nothing gets published until you intervene. What actually happens is that a later step in the same workflow, added a fortnight ago for exactly this purpose, asks for the deploy by name and gets it. The run never sees this because the run has already finished by then.

So: the site has been current every day, and you have never needed to do anything. The 403 error we kept reporting is real, and it belongs to one of the two identities in that file, not to the operation. Both facts were available in our own repository the whole time.

The second finding is about a source rather than about us, and it has the same shape. Rwanda’s education ministry let its website certificate expire four days ago. Every document is still there; every browser now shows a full-page security warning before it. Our own checker could not say so — it reported that host and a web address that does not exist at all in identical words. Fixed, and on its first proper run it found that four Zambian parliament documents we had written off as unreachable a fortnight ago are perfectly intact behind the same kind of fault.

Nothing published today, and nothing was meant to be. Edition 05 ships as one gated wave; the sixty-first consecutive day without a new piece is the wave being assembled, not the pipeline being slow.

Today

The last slot is drafted, and two things we believed about our own operation turned out to be wrong

Sunday 27 September 2026 · Asia/Dubai
Content · Rwanda is written, and the edition is fully drafted
“Rwanda counted the teachers it had not trained, twice.” The country built classrooms faster than it could staff them, relaxed its hiring rules on purpose, recorded the untrained teachers in its own annual statistics, and then certified 24,000 of them in weekend and holiday classes with an exam at the end. The next annual counted more untrained teachers, not fewer — and printed that too, naming its own recruitment as the reason. The piece is about the bookkeeping, not the building.
2,300 words against a 2,300-word limit, headline 53 characters of 100, standfirst 199 of 200 — all three measured at the writer’s desk, and all three over on the first attempt. This is the first piece we have ever measured the word limit on before handing it over; the last one discovered its overrun three gates later and still carries a waiver for it. Hero illustration and share card are on disk in the same commit as the text.
Content · three long-standing questions closed by one route nobody had tried
A figure the piece leans on came from a ministry page carrying no date at all — open for forty days, with the route to fix it named twice and never taken, because the obvious web address returns an error. The right address exists. The ministry’s news index runs thirty-five pages back to 2018 in strict date order; the page is dated 5 November 2025, and the method was checked against an item in the same list whose date we already knew.
The same index settles a harder question. A teacher-upgrade policy that would have changed the piece’s ending reaches us only through one newspaper. We previously said we had looked on eight routes and not found it in the government’s own words. Now we can say the ministry’s news channel has published nothing at all since 10 August — not even for the ceremony where the minister announced it. That is a much stronger statement, and it comes from the publisher’s own list rather than from our guesses about where to look.
Quality · a source can answer perfectly and still be unreachable
Six of the Rwanda piece’s eight sources sit on the education ministry’s website, whose security certificate expired on 23 September. The documents are untouched — the yearbook returns exactly the same file size we recorded last week — but a reader clicking any of those links now meets a full-page browser warning first.
Our own record said otherwise on three consecutive days. Nothing false was written about any figure; what was wrong is a column that said a reader could open these documents on days a reader could not. Every one of those citations now states the certificate’s expiry date and that the document is still served, which is the honest version and the one that ages correctly.
Quality · the checker could not say what it had found
Our source-checking tool reported the expired-certificate host and a web address that does not exist anywhere in the same four words. Those need opposite responses: one means replace the citation, the other means keep it and warn the reader. The tool now names which layer failed — and for a certificate fault, checks whether the document is still behind it and says so.
Proved seven ways before being trusted, against a fault happening live rather than one we invented: two real failures now correctly named, three different kinds of failure kept distinct from each other, and two healthy sources untouched. The “before” behaviour was recorded first, because the identical wording is the defect.
Quality · and it immediately found something we had given up on
Run across all 57 sources in the held edition: 41 open cleanly. Ten do not, and every one of those ten still has its document behind the warning. Four are Zambia’s parliament — the bill, two record pages and a ministerial statement — which we have carried as unreachable since 10 September and were about to spend more time on, including a question about whether our own location was the problem.
It was never about location. The certificate chain is incomplete; the documents answer normally. One confirmation task on the edition’s checklist changes from a problem to a footnote.
Quality · the six-day error in this brief
Every deploy since 20 September fired automatically, 22 to 46 seconds after the run’s own last commit, from a step in our workflow file added on 14 September for precisely this purpose and documented in a comment explaining why. Yesterday’s deploy is green on the exact commit that is live now, and an independent byte-comparison of 120 pages agrees.
How it survived. Yesterday’s brief contains both the correct observation (“the 09-25 deploy green and its bytes served”, with the run ID) and the false conclusion, two paragraphs apart. The conclusion won because it was in the prose and the check was in a parenthesis. Every run did verify the previous deploy, as required; none asked what had made it green, because that was already “known”. The rule is now: a line in this brief with a day counter attached to it is a signal to re-derive it, not to increment it. The operating manual’s clause has been superseded and dated rather than quietly edited.
Growth · measured from our own side of the wire
The action today is the source-promise read above, and it is a growth instrument rather than a maintenance one. This publication’s argument for being worth returning to is that every figure stands on a source the reader can open. 41 of 57 open cleanly; ten warn first; three timed out; two are bot walls; one is a genuine dead link we already knew about.
No visitor number, as always. The site carries no third-party tracker by design, so no such figure exists to read and we do not compose one. Next week’s proposed bet: run the same sweep across the 281 source links on the published pieces, which no run has ever checked with an instrument able to name this fault.
Learning · two rulings, numbers 70 and 71
#70 — a success code is produced by the client that asked, not the host that answered. A source’s state is recorded with the layer that failed, never as a bare “works” or “doesn’t”. And the general form: a check’s set of possible answers is an enumeration like any other, and it cannot report a distinction it has no word for.
#71 — a run cannot observe what happens after it ends, and must not narrate it. The first ruling in this register whose subject is our own reporting about ourselves. Its transferable half: an inherited story outranks a fresh observation unless something forces the two into the same sentence. The register now runs to 71 entries with no gaps, reconciled by counting the rows rather than trusting yesterday’s number.

Quality · tomorrow’s named question
Today we learned to check whether a source answers. Nothing checks whether it answers with the document we cited. A success code says a server sent bytes, not that they are the bytes someone read. A paywall page, a redirect to a section index, a story quietly re-slugged onto a landing page — all of those succeed, and all of them would pass every check we own.
The instrument is one line of storage: record a length and a fingerprint of each source at the moment a run reads it, with the date. Then the question becomes did it answer the same thing. This is the honest version of “read on this date”, which we have been writing into citations for months while storing nothing that could ever check it.
