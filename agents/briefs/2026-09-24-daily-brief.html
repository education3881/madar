Nothing owed by you · no dark day · but yesterday’s deploy is red

State verified from git and from the live origin before anything was planned. Tree clean, local and origin at the same commit, no missed day. The 09-23 deploy failed — and the first thing this run did was establish whether that meant the site was broken. It does not.

The build passed. The deploy passed. The byte-compare against the live origin, inside the same job, passed on all five files. The failure is a step that runs after it, and the publication it was checking was in perfect health the entire time. An independent instrument agrees: the origin matches our build exactly — 120 URLs, zero drift.

Today changes no served byte. Every file touched is outside the published site. All 24 standing assertions were run against this exact build — 21 gate the deploy, and the three that do not were run by hand. One of the 24 is new today.

Manager → Founder

The gate failed and the publication was fine. It has been a coin flip since the day the feeds shipped.

One of our checks asks a reasonable question: can a reader who subscribes to our feed poll it cheaply, getting back “nothing new” instead of the whole file? To ask it, the check fetches the feed’s version tag, then sends that tag back and expects to be told “still current.”

GitHub unpacks each of our deploys onto more than one server, and it stamps the version tag from the moment of unpacking. Those servers finished one second apart. So the same file has two version tags — identical content, two labels. The check’s two requests go out separately and land on whichever server answers, so roughly half the time it sends one server a label minted by the other, and gets told “never heard of it.”

We measured it twelve times before touching anything. Every single refusal was the label mismatch, and never once an actual refusal to honour a label the server held. Both stamps were still being served a day later, so this is not something settling down. It is permanent. The gate passed on Monday and Tuesday by luck.

The obvious repair is to loosen the check. We did something better, because asking why it flaked was cheap and loosening it would have hidden the real question: if a server can hand out two labels for one file, does it also hand out two files? The old check could never have told us — it compared labels and never once downloaded the thing they label. The replacement downloads it every time. Many labels are tolerated; many files are not.

A gate that was wrong about a site that was right, and a recon that had gone stale in its own instructions

Thursday 24 September 2026 · five functions, all five delivered
Quality · the red deploy, diagnosed and repaired
Root cause established by measurement rather than inference, then rebuilt as standing assertion 24. The fix is to do what an actual feed reader does: hold one connection and ask on that one, because a single connection reaches a single server holding a single label. Against the live site: sixteen of sixteen honoured, one file per feed. It is stricter than what it replaces — the old step wanted one success, this wants all of them.
The first version of the repair was wrong, and proving it is what caught that. We require every new check to be shown both that it stays quiet on a known-good case and that it fires on the fault it exists for. The known-good case here is the real 23 September condition — two labels, one file — and the check failed it on the first run. That failure is what replaced a tolerance with the honest instrument. Proved seven ways before it was allowed near anything.
And we cannot apply it — this is the one thing worth your attention
The broken step lives in a deployment workflow file, and this identity is refused permission to write those files. Re-tested today on a throwaway branch; refused, verbatim, as in the two previous attempts. The one-line patch is written, staged in the repository, and escalated on issue #7.
What has changed about that issue is its cost. Until today it held a repair that was an improvement and could wait. It now also holds a repair for a gate that is failing at random on a healthy site. The expense is not the unapplied patch — it is that every future run must now spend its first minutes deciding whether a red deploy is real. A gate that cries wolf is worse than no gate. Stated default, stated date: if neither the permission nor a hand-applied patch arrives by the 28 September review, that cost simply continues, and the review will say so again.
Content · Rwanda re-verified, and the recon had gone stale in its own instructions
The sixth and last row of Edition 05, unclaimed for ten days. Its August recon was re-read against the web as served. Nothing has gone false — all three registers still serve, and the piece’s central sourcing finding holds word for word. Verdict: proceed.
But the calendar moved through the recon’s drafting instruction. The recon says of Rwanda’s new five-year teacher-training programme: “the first cohort has not yet enrolled” and “write it in the future tense.” The programme was announced to begin in September 2026. Today is 24 September. A writer obeying our own recon would have put a false tense into the piece, and the recon would have been the reason. It is the edition’s third case of a plan outliving its date — and the first one caught before drafting rather than after banking, which is the entire return on re-verifying a recon before using it.
Content · both standing blockers close, and the subject wrote the story down itself
Rwanda certified 24,000 previously unqualified teachers. Since August the piece has been blocked on a simple question: 24,000 out of how many? Without it the number is impressive and unreadable. The route the recon named — a 2024/25 yearbook — does not exist; the ministry’s most recent is 2023/24. It holds the answer: 10,898 pre-primary plus 68,326 primary teachers.
And the same register counts the debt in the ministry’s own voice, which nobody had looked for: 5,162 untrained pre-primary teachers (47.4%) and 22,160 untrained primary (32.4%) — roughly 27,300, in the school year the programme opened. It attributes the decline to “newly recruited primary teachers who may not have received training.” The government wrote the shortfall into its own statistical annual. That is the piece’s thesis, stated by its subject, and it is a better citation than anything the funder’s account carries.
Content · a new blocker that changes the ending
On 20 August a minister announced a five-year window for teachers to upgrade beyond the qualification the 24,000 just earned. If it holds, the argument improves: not incur, disclose, retire, but incur, disclose, retire, and immediately re-open at a higher bar — a system treating a qualification floor as something that moves.
It reaches us only through a government-adjacent newspaper quoting a speech. An ending is load-bearing by definition, so it may not carry one until a first-party register is read. Owed before commission.
Growth · we verify our way into print and not our way out of it
Yesterday’s question asked which of our text is meant to be published verbatim without saying so. The answer: four of twenty-five files carry the marker our new check reads. Outside it sit tile captions in both languages, hashtags, and a subscriber welcome signed “— The Editors.” That is copy, not commentary.
It was hiding a plain error. Our Instagram tile said “Sierra Leone marked ten years of its Free Quality School Education policy in 2026” — and the piece it advertises says “From 2018…” That is eight years, and the piece marks no anniversary at all. Four instances, three files, both languages, up to 121 days, one of them the posting kit. All corrected — by removing the claim, not by substituting a different anniversary.
Growth · the finding under the finding
We caught this exact error the same week, on a different piece, and killed it. A May editorial brief reads: “The phrase ‘ten years on’ in the slate’s framing is wrong.” Same reflex, same fortnight. The Editor stopped it on the way into a piece. Nothing stopped it on the way out, because nothing reads the distribution copy — and five days later it went into the grid.
The instinct is to mark up the other twenty-one files. That reproduces the defect — the marker is a comment a writer can forget, which is exactly why four files have one and twenty-one do not. What is owed is the inversion: postable copy lives in a declared place and everything there is checked, the way a piece’s source list works because the format demands it. Default-in beats default-out. The failure mode of default-out is silence.
Research · ruling 63, a validator is not the content
An identifier minted by the machine that stores a file is a property of the storage, not of the file — two copies of identical content get different labels. And the operational half: a check that makes two requests has run two experiments, so anything the infrastructure may vary between them is a variable, not a constant.
It sits beside two we already had. Ruling 57: two equal counts are not two equal sets. Ruling 60: the same commit built on two machines printed different dates. Now: the same bytes stored on two servers mint different labels. In each, a value that varies with where it was computed got mistaken for a value that varies with what it describes. Filed with the register’s three counts moved in the same commit, which is what that rule asks for.
