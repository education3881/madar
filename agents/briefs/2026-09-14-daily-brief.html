The attribution verb — the surface last Sunday’s review named as forward — was tested, and it bit. The review predicted that said · announced · confirmed · found · estimates each promise a different register and that nothing checks them. Research
Ruling #50 — a correction has a blast radius. When a verdict changes a piece, it changes every artefact composed from that piece; the correction is finished when the descendants have been re-read, not when the article is fixed. Every check we own was structurally blind to it: the Verifier traces the piece, the thirteen assertions enumerate dist, the 08-23 perimeter rule reaches rendered artefacts and a markdown packet is neither published nor rendered — and the packet’s own header promised “no figure appears here that is not in the shipped piece,” while the defect was not a figure but a noun.
Seventh member of the enumeration family and the second to sit outside dist, but it asks the family’s question backwards: not what can this check not see? but what does this correction not reach? Series now #1–#50, no gaps. Housekeeping owed to Sunday: the canonical table still ends at #48, with #49 and #50 living as register rows — deliberately left for the consolidation, because a daily run merging that table by hand is how the three-way disagreement of 09-13 was created.
Operations
OPEN The run cannot edit its own CI, and found out by being refused. The new assertion was written into the deploy workflow beside the other eleven, exactly as the rule requires, and the push came back: refusing to allow a GitHub App to create or update workflow … without workflows permission. That is not grantable from inside a workflow, deliberately — a job that can rewrite its own workflow can grant itself anything. The design is right. This morning the operation moved to the cloud to stop depending on one person, and by the afternoon had found the one class of change that still does.
The gate was not dropped. It is invoked from web/package.json as postbuild, which npm run build — the deploy job’s own command — runs; a failure there fails the build and nothing deploys. Proved through that entry point: exit 0 on the real tree, exit 1 with the defect reinjected at source. Stronger in one respect, since it now gates every local build too, and weaker in another: astro-pages.yml stops being the complete register of what gates the deploy. That is issue #6, and it is yours — the clean fix needs a credential only you can create. Three options, a recommendation, and a stated default (document the split) applied on 2026-09-20 if it goes unanswered.
