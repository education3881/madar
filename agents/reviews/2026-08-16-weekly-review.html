The recurring defect class: the push gap

Three in eight days — 2026-08-09 (named on 08-10), 2026-08-12 (named on 08-13), and the current one running 2026-08-12 → 2026-08-16, five days and four artefact-days deep. Each run handled it correctly in isolation: verified state, named it plainly, rolled the block forward. That correct local handling is exactly why it recurs — nothing about the second unpushed day looks any different from the first, so nothing escalates. Two things do change with duration: the founder's proof-of-work contract is delivered by the push, not by the file on disk (an unpushed brief is an undelivered brief); and the risk is not loss but contamination — the longer a block sits, the more a single git add -A sweeps, and the wider the window for a founder push to land underneath it, which has now happened four times.

Codified into the RUNBOOK this week — rule 1

The QA link sweep covers site chrome, not just content links. The daily pass enumerates every href and src emitted by Base.astro, SiteHeader.astro, SiteFooter.astro and any layout-level component, and asserts each resolves in dist — swept over the built HTML, not read from the source. And: a link in the chrome is a promise the build must keep — if the target does not exist, either build the target or remove the link in the same commit. A nav item pointing at an intention is a defect, not a placeholder.

Codified into the RUNBOOK this week — rule 2

A push gap escalates; it does not simply roll forward. At ≥1 day unpushed, the push block moves to the top of the brief, above Yesterday, with an explicit "N days unpushed · M artefacts staged" line. At ≥3 days unpushed, the run's first action — before adding anything new — is to reconcile the working tree against the brief ledger (every artefact each unpushed brief claims is still on disk and still complete) and to re-check git log origin/main -1, with the reconciliation written into the QA log. The operation does not own whether the push happens; it owns whether the block stays clean and legible while it waits.

The week's compounding asset: the scoped-instrument family, now named

Four rows turned out to be filing four shapes of a single rule. Consolidated:

ShapeRowThe failure it names
A pledge is a scoped instrument15Progress figure quoted without its scope-definition-with-date

The one rule underneath: a claimed quantity is unreadable without the instrument that produced it — scope, base, denominator and ruler are four names for the same missing half of a figure. The verification move is a single question asked of any headline number: "…out of what, produced how?", with both answers required from the source rather than reconstructed by arithmetic. This is the seven-axes checklist's sibling — the axes ask what a number is conditioned on; this family asks what made it. None of the four needed a new number; they ride #21/#22/#24/#25, which is what a maturing checklist looks like.

Ruling #29 — a lineage claim is a figure

One promotion, and the first new number since 2026-08-02. Row 22's Sudan method note moves from row-level to numbered: a claim that instrument B is, descends from, continues or is a phase of instrument A is a citable figure, carrying its own provenance axes — same programme, formal successor, rebrand, or independent parallel — and it must be traced verbatim to a source that states the relationship, exactly as a number is traced to a source that states the value. Same place plus same technology plus same look ≠ same instrument.

It earned the number on three tests. Nothing existing covers it — the seven axes and the scoped-instrument family both scope a number; this scopes an identity, and a draft can carry every figure perfectly and still be wrong in its spine. It caught a live one: the tempting Sudan spine, "the wartime digital learning spaces run the platform Sudan invented," is supported by place, technology and idea, by no served-text source stating the identity, and is contradicted by one register — War Child's 2025 country list, which does not include Sudan. It generalises across the slate: Egypt's drive-versus-drive, Rwanda's CBC descent, every "Phase II," and every "building on the success of" sentence in a press release, which is where lineage claims are manufactured. The Verifier's trace list gains a lineage claim traced to a source stating the relationship: ☐ row whenever a spine depends on it. Series check: #1–#29, no gaps, no duplicates.
