# RUNBOOK — how Madār operates day-to-day

> **For the Manager opening a new session.** Read this first, then `/agents/01_manager.md`, then yesterday's status log at `/agents/logs/manager-status-<yesterday>.md`. After that, brief all four departments **in parallel** within the first ten minutes.

---

## The five things to know in one screen

1. **Vini is off operations.** He reads daily, weighs in when he chooses. The Manager runs the publication. Escalation list is short (geo/topic scope, brand, paid infra, reputation).
2. **Deploys are automatic.** Every push to `main` triggers GitHub Actions, which builds the Astro site under `/web/` and publishes to GitHub Pages within ~90s. There is no manual `dist/`, no `gh-pages` worktree, no terminal beyond `git push`.
3. **The publish gate.** A piece does NOT ship until: (a) Editor verdict file in `/content-drafts/verdicts/<slug>.md` is `approve`, AND article md is in `/web/src/content/articles/<slug>.md` with `approved: true`; (b) Designer hero still exists at `/web/public/stills/<slug>.svg` and is committed; (c) Web Developer's `npx astro build` produces clean `dist/` AND the QA spot-check passes.
4. **Parallel, never serial.** When the Editor commissions a piece, the Manager **simultaneously** briefs the Designer (hero brief), the Web Developer (integration window), and Growth (social window). The Editor's verdict is the LAST gate, not the first dispatch.
5. **Quality over slot.** A thin issue is better than a weak piece. The Editor's parks are final at the operational level; the Manager backs them without exception.

## What a normal commission looks like

The Editor wants to commission a new piece on, say, the Saudi ECE workforce. The right flow:

1. Editor writes the brief at `/content-drafts/briefs/<date>-<slug>-brief.md` with mandatory sources, named humans, voice notes, the five-test rubric expectations.
2. **At the same moment**, the Manager:
   - Briefs the Designer with the hero brief (theme, mood, dominant emotion, two refs, a "what this piece is NOT" line). Designer can start on the still while the Content Creator is researching.
   - Tells the Web Developer to expect an article slug landing in `/web/src/content/articles/<slug>.md` and to keep QA capacity reserved.
   - Tells Growth a publish window so social drafts can be queued.
3. Content Creator does the research dossier first, then the draft, in the envelope format defined in `/agents/06_content_creator.md`.
4. Editor judges via the five-test rubric: approve / return-with-notes / park.
5. If approved, the article is moved to `/web/src/content/articles/`, Designer's still is in `/web/public/stills/`, Web Developer runs build + QA spot-check.
6. Manager confirms all three publish-gate items are in the repo, then `git push origin main`. The Actions pipeline deploys within 90 seconds.

If at step 5 the Designer's still isn't ready — **hold the deploy**. Do not push. Write the held-status into today's manager-status. The piece waits.

## The terminal interaction with Vini

Vini does not enjoy terminal pushes. The deploy automation eliminates the per-change push, but the one push per session that lands a session's work on `main` is still Vini's. End each session with a clear, single-line instruction:

```bash
cd "/Users/vini/Documents/Claude/Projects/Educational Website" && git add -A && git commit -m "Madār — <date>: <one-line summary>" && git push
```

That is the only terminal text the Manager should ever ask Vini to paste. If you find yourself writing a multi-line shell block to send him, you have lost the plot — the right fix is to make the Actions pipeline do that work.

## Failure modes to avoid (from 2026-05-26)

- **Serialising parallel work.** Briefing the Designer "for tomorrow" after the Editor approves is the failure that shipped the Bahrain piece without its hero still. The Designer is briefed at the moment the Editor commissions, not the moment the Editor approves.
- **Loading brand-critical chrome via `<img src>`.** The wordmark must be inlined at build time, with a CSS-only typographic fallback. See `/agents/03_web_developer.md` § "The 'never ship without inlining' rule."
- **Hardcoding piece references in shared pages.** The Arabic home page hardcoded a reference to the Jordan piece; when Jordan was parked, the Arabic page broke. Any page that references a specific piece needs to be regenerated when that piece's status changes, OR — better — it should iterate the collection, not name slugs.
- **Letting the QA pass slip.** The Web Developer runs the QA checklist daily and within 30 minutes of every deploy. It is not optional.
- **Asking Vini to "approve" content.** He has stepped out of editorial decisions. The Editor approves; the Manager backs the Editor; Vini reads.

## Prevention rules from the weekly review (codified)

- **An article's assets ship in the SAME commit as its text — never in a follow-up (codified 2026-06-14).** On 2026-06-10 a founder push (`feb98b1`) landed mid-run, and its `git add -A` swept the two finished Iqra article files to origin *ahead of* the hero still, sitemap and reciprocal rails — leaving the live Iqra pages referencing a hero still that 404'd until the completion commit caught up. A piece is never partially shippable: the invariant is *no article live without its hero still*. Two binding behaviours close this: (1) **write the hero still and any article-bound asset to disk immediately after the article text, before composing any push block** — never leave assets for a "completion commit"; (2) **re-check `git fetch origin && git log origin/main -1` right before composing the push block** — a founder push can land at any moment (briefs land ~08:00–08:30; agent runs overlap), and if origin has moved, stage so that no commit can leave the live site referencing an asset that isn't yet on origin. The push block stays a single `git add -A` line for Vini's convenience; the *ordering of writes within the run* is what protects the invariant, not pathspec gymnastics in the block. (Memory: `edu-website-push-race`.)

- **Capped frontmatter strings (`dek`, `title`) are code-point-counted at COMPOSE time, never first measured at the gate (codified 2026-06-24).** The 200-char `dek` cap bit twice in four sprint ships — Korea (06-17, EN+AR deks over, tashkeel counting) and Oman (06-20, EN 211 → 184) — each caught at the publish gate and fixed clean. The gate catching them is the system working, but a defect found at the *last* gate is a defect that ate a build cycle: the cap belongs upstream. Two binding behaviours: (1) **the Content Creator / Arabic Content Creator counts code points on the composed `dek` and `title` before handing to the Editor** — `python3 -c "print(len(open('x').read().strip()))"` or the copy-paste check in `2026-06-17-arabic-dek-character-cap-includes-tashkeel.md`, **counting Arabic tashkeel as +1 each** (a fully-voweled AR dek fails at ~150 visible chars); (2) **the Editor / Arabic Editor verdict carries an explicit `dek ≤200 (code points, tashkeel incl.): ☐` checklist line** so the cap is verified before the piece reaches the gate, not at it. The publish gate stays the backstop; it should no longer be the first ruler. (Guidebook: `2026-06-17-arabic-dek-character-cap-includes-tashkeel.md`.)

  - **Enforcement addendum (codified 2026-07-27, weekly review).** The dek/title cap bit a **third** time on 2026-07-22 — netherlands-doorstroomtoets composed a 250-code-point `dek` against the 200 schema cap, caught at build and fixed same-run. Three strikes (Korea 06-17, Oman 06-20, Netherlands 07-22), every one caught at the *gate/build*, never at *compose* — which means the 06-24 rule is written but not being executed at the ruler it names. The rule does not need rewriting; it needs teeth. Binding from this week: (1) **the draft hand-off to the Editor is INCOMPLETE without the recorded count** — the drafter pastes `dek: NNN/200 · title: NN/100 (code points, tashkeel +1 each)` into the verdict-request, and a hand-off missing that line is returned unread, not verified-then-flagged; (2) **the Verifier's trace list carries a `dek/title within cap at compose: ☐` row**, failed if the count line is absent from the hand-off (an unmeasured cap is an open item, exactly like an untraced figure). The build gate remains the backstop and will keep catching it; the point is that a cap first discovered at the backstop has already eaten a cycle. A defect class that recurs after codification is an *execution* gap, not a knowledge gap — close it at the hand-off, where the ruler lives.

- **After a wave flip, the flag sweep INVERTS — know which mode the corpus is in (codified 2026-08-09).** The held-leak sweep asserts *zero held slugs in dist/sitemap* while a wave is held; the moment the wave's flags flip `approved:true` and ship, that assertion passes **vacuously forever** — there is nothing held left to leak, so a sweep still running in held-mode is a green light wired to nothing. The QA pass after any publish gate must switch its assertion to the inverse: **`approved:false` count in the build path = 0** (all-approved), plus the positive checks the held-mode sweep never ran — every new slug resolves EN+AR on the *deployed* sitemap, every new hero still resolves in built article HTML. The 2026-08-09 post-launch run did this correctly by judgment; this rule makes it the required shape, not a judgment call. General form: **a QA assertion is scoped to a corpus state; when the state changes, re-derive the assertion — don't re-run it.** (Same family as #16/#17: verify the thing itself, in the environment and *state* that judges it.)

- **The first run after ANY dark gap is a RECOVERY run, with a fixed shape (codified 2026-07-02).** Dark gaps — days with no runs because the app wasn't launched — have now occurred three times, escalating: 1 day (06-13), 3 days (06-21→23), 6 days (06-26→07-01). Each time the resume was improvised; the improvisation is now the rule. On any gap ≥1 day, the next run: (1) **verifies state from git + the live site, never from the last brief** (the brief is the gap's *before* picture — memory `edu-website-state-verification`); (2) **re-verifies the freshness of every banked candidate before drafting from it** — a banked recon ages; load-bearing URLs and figures are re-checked live (per-draft Test 1 discipline, but explicitly triggered by the gap); (3) **ships at most one piece** — one missed day (or six) earns one clean recovery day, never a forced double-batch (standing rule #1); (4) **states the gap plainly in the brief/review** — dates, length, what didn't run — no dressing up. The gap's *trigger* (app launch) is structural and founder/platform-side; what the operation owns is the shape of the first run back, and that shape is no longer discretionary. (Origin: 06-24 + 07-02 weekly reviews.)

- **Generated artefacts that must mirror the article set are build-generated, never hand-maintained (codified 2026-06-07).** A hand-built `sitemap.xml` or any hand-kept list of slugs/hreflang pairs is a *drift defect waiting to happen*: it is correct the day it is written and silently wrong the next time an article is added or parked. Anything that must equal "the current set of articles" (sitemap, hreflang alternates, archive indices) must be generated from the content collection at build time. Action of record: replace the static `sitemap.xml` with the `@astrojs/sitemap` integration (carried since the 2026-06-04 weekly signal; FUSE boundary on `node_modules/.vite` means the install/build runs via the /tmp route-around or a clean Web-Developer checkout). Until that lands, the static sitemap must be re-validated against EN/AR parity in every publish gate.

- **The QA link sweep covers SITE CHROME, not just content links (codified 2026-08-16).** On 2026-08-16 the weekly review found that the footer's **RSS link had pointed at a non-existent `/rss.xml` since the initial publish on 2026-05-25** — a hard 404 in the footer of every page, in both languages, for 83 days and **35 QA passes**. Nothing was wrong with the check that ran; the wrong thing was its *scope*. The daily sweep resolves `related:` refs, hero stills, hreflang pairs and article slugs — every link the *content* generates — and had never once resolved the links the *layout* generates, because those are hard-coded in components and feel like furniture rather than data. Furniture 404s just as loudly. Binding from this week: (1) **the QA pass enumerates every `href`/`src` emitted by `Base.astro`, `SiteHeader.astro`, `SiteFooter.astro` and any layout-level component, and asserts each resolves in `dist`** — a one-line sweep over the built HTML, not a reading of the source; (2) **a link in the chrome is a promise the build must keep** — if the target does not exist, either build the target or remove the link in the same commit; a nav item pointing at an intention is a defect, not a placeholder. General form of the miss, and the reason it stood so long: *a green check is scoped to what it enumerates; a check that never enumerates a surface cannot fail on it.* (Same family as the 2026-08-09 flag-sweep inversion — an assertion that passes vacuously is a green light wired to nothing.) Action of record: both feeds shipped in the same review that found the gap (`web/src/pages/rss.xml.ts`, `web/src/pages/ar/rss.xml.ts`, autodiscovery in `Base.astro`), so the promise is now kept rather than withdrawn.

- **The QA pass sweeps links outward AND pages inward — the orphan sweep (codified 2026-08-17).** Yesterday's chrome-sweep rule ran green on its first day: 98 unique targets across seven pages, zero unresolved. Running it exposed the question it structurally cannot ask. **A link sweep checks pages that are pointed at; it can never find a page that nothing points to.** `/madar/valence/` — a 540 KB standalone instrument shipped 2026-08-08 — had been served for nine days with **zero inbound links from anywhere on the site, no sitemap entry, no canonical, no social card, and no link back into the publication**. Cause: it is served from `web/public/` as a static file, and `@astrojs/sitemap` enumerates the *Astro route graph*, which files in `public/` never enter. The tell had been sitting in the QA numbers the whole time — **82 built pages against 81 sitemap URLs**, a difference of exactly one that no check compared. Binding from today: (1) **the QA pass asserts `served page count == sitemap URL count`**, and any difference is named and explained rather than tolerated — the cheapest orphan detector available, and it costs one line; (2) **every page the build serves must have at least one inbound path** — a link from another page or a sitemap entry, ideally both; (3) **anything added under `public/` that is meant to be found is listed in `sitemap({ customPages })` in the same commit** — the config now says so in a comment at the point of change; (4) **an unlinked page is the mirror of yesterday's defect** — a nav item pointing at an intention is a promise the build breaks, and a served page nothing points at is a promise never made. Third member of one family: the **flag-sweep inversion** (08-09, an assertion that passes vacuously), the **chrome 404** (08-16, a check scoped to content never enumerated the layout), and this. General form, now stated three ways: ***a green check is scoped to what it enumerates*** — so the standing counter-discipline is to ask each run what the current sweep cannot structurally see. Action of record: `customPages` added, VALENCE given canonical + Open Graph + Twitter card + feed autodiscovery + three links back into Madār; sitemap 81 → 82, matching the page count exactly. Deliberately **not** done, because it is an editorial call and not a QA fix: placement in the site chrome, an `og:image`, and the Arabic-side question (see `agents/growth/2026-08-17-orphan-page-audit-valence.md`).

- **A resolving asset is not a usable asset — the consumer-format rule (codified 2026-08-18).** Third day running that the sweep found what the previous day's sweep could not structurally see, and the first one found by *asking the question deliberately* rather than tripping over the answer. Yesterday's forward question was: the sweeps check that a link resolves and that a page is reachable, but neither checks that the thing at the other end is **usable by the consumer that will fetch it**. Applied to `og:image`, it failed immediately. Every article, both languages, has declared its hero still as the share card since the first publish on **2026-05-25** — and every hero still is an **SVG**, which **no major social consumer renders** (Facebook, X, LinkedIn, Slack accept PNG/JPEG/WEBP/GIF only). The file existed, the URL was absolute, it resolved on every QA pass ever run, and for **83 days** every share of every piece travelled with **no card image**, while the log recorded the image as present. The pages also declared `twitter:card = summary_large_image` — a promise of a large image kept with nothing. Binding from today: (1) **the QA pass asserts no `og:image` ends in `.svg`**, and more generally that every asset handed to an external consumer is in a format that consumer accepts; (2) **a promise in the metadata is a promise to a machine we do not own** — verify it against *that machine's* accepted formats, never against our own filesystem; (3) **the raster card is generated from the still, never hand-drawn twice** (`public/stills/*.svg` → `public/og/*.png`, 1200×600, sharp/librsvg, ~10 KB each), so the two can never drift; (4) **look at the output** — the Arabic wordmark on the new VALENCE card rendered with broken joins until `letter-spacing` was removed, and only inspecting the PNG caught it (tracking is never applied to Arabic). General form, now the fourth statement of one rule: ***a green check is scoped to what it enumerates*** — and "resolves" is a narrower enumeration than "works." Next surface with the same shape, named so it is not forgotten: **the feeds** — well-formed and 38 items each, and nothing has ever verified that an item renders legibly in a reader, that AR items carry their direction, or that links resolve from outside our origin.

- **A push gap escalates; it does not simply roll forward (codified 2026-08-16).** Push gaps are now the operation's most frequent defect class: 2026-08-09 (named 08-10), 2026-08-12 (named 08-13), and 2026-08-12 → 08-16 (five days, four artefact-days, named in the 08-16 weekly). Each run handled it correctly in isolation — verify state, name it plainly, roll the block forward — and that correct local handling is exactly why it recurs: nothing about the second unpushed day looks different from the first. It should. Two things change with duration: (1) **the founder's proof-of-work contract is delivered by the push, not by the file on disk** — a brief he cannot open did not reach him, so an unpushed brief is an *undelivered* brief, and the CHARTER's "a day with no brief is a failed day" applies to delivery, not authorship; (2) **the risk is not loss, it is contamination** — the longer a block sits, the more the single `git add -A` line sweeps, and the wider the window for a founder push to land underneath it (the 2026-06-10 push race, now seen four times). Binding shape: **≥1 day unpushed** — the push block moves to the *top* of the brief, above Yesterday, with an explicit "N days unpushed · M artefacts staged" line; **≥3 days unpushed** — the run's first action, before adding anything new, is to **reconcile the working tree against the brief ledger** (every artefact each unpushed brief claims is still on disk and still complete) and to **re-check `git log origin/main -1`**, because the block is now large enough that a bad sweep is expensive; the reconciliation is written into the QA log. What the operation owns is not whether the push happens — that is the founder's one action — but whether the block stays clean and legible while it waits.

- **Founder-push availability is a capacity constraint, not a compliance failure (codified 2026-08-30).** The 08-16 escalation rule worked exactly as written through 08-25 → 08-29 — block reconciled, top-of-brief, ledger checked daily — and the gap still reached six days, because every escalation the rule prescribes targets the operation, and the operation was never the constraint: the tree was clean, the block was staged, and the founder's single action did not run on four consecutive days. When that is the shape — **≥3 consecutive staged-but-unrun days with a clean, reconciled tree** — the defect class changes and so does the response: (1) **stop escalating tone daily** — the fourth identical P1 teaches nothing; keep the block at the top of the brief with the day count and leave it there; (2) **plan as if the guaranteed push window is weekly** (Sunday, when the founder reads the review) — nothing time-sensitive is staged assuming same-day deploy, and wave gates, announcements and anything that binds an external system to a URL are scheduled onto *push-confirmed* state only, per the state-verification rule; (3) **the weekly review carries the standing founder question** until he answers it once: *keep the daily-push design, or formalize the weekly window and let the operation batch deliberately.* What the operation owns is a block that lands clean whenever the window opens; what it must stop doing is designing days around a cadence the constraint does not support.

- **The QA perimeter includes the artefacts the operation renders for humans, not only the ones it publishes for readers (codified 2026-08-23).** On 2026-08-16 the daily-brief template lost its `main` container wrapper; the **two briefs that followed rendered edge to edge**, and nobody noticed until the 08-18 run happened to look at one. Every sweep we own — build, parity, chrome, orphan, consumer-format — enumerates `dist`, because `dist` is *the publication*. The brief is not in `dist`. Neither is the weekly review, nor any memo. And the brief is the single artefact the CHARTER names as the founder's proof-of-work contract: the one thing he actually opens. **The publication was checked six ways while the only page he reads was broken.** Binding from this week: (1) **every HTML artefact the operation renders for a human — daily brief, weekly review, memo, packet — is opened and looked at before the push**, and carries the same container/wrapper assertion the site pages get; (2) **a template change is a change to every artefact that template will ever produce** — when a shared brief/review template is edited, the run re-renders one artefact from it and inspects the output, exactly as ruling #16 requires for the site; (3) **the founder-facing surface is in scope by definition** — if he opens it, we check it. Fourth member of the *enumeration* family and the first to sit outside the publication entirely: the flag-sweep inversion (08-09), the chrome 404 (08-16), the orphan sweep (08-17), the consumer-format rule (08-18) all found gaps *inside* `dist`; this one found the gap in what `dist` **is**. General form, restated: *a green check is scoped to what it enumerates* — and everything we have ever enumerated was the product, never the proof of work.

- **A held file is not part of the publication — nothing derived from the content set may read it (codified 2026-09-06, weekly review).** The held-leak sweep has asserted *zero held slugs in dist and the sitemap* on every run since the flag became the hold (ruling #18), and it has been green every time. It never enumerated **dates**. `web/src/lib/sitemapLastmod.mjs` resolves the index pages' `<lastmod>` as *max(chrome, newest file under `web/src/content/`)* — and a held draft is a file under `web/src/content/`. Twice this week a deploy that touched **only a held article and its still** moved the live home, Arabic home, About and both Editions pages' `<lastmod>` to the held file's commit time (**08-30**, the Sierra Leone AR, and **09-02**, the Sudan EN draft — both recorded in the QA logs as "origin sitemap lastmod = <commit time>" without anyone noticing that no served byte had changed). A crawler was told five live pages changed when nothing a reader could see did — the exact "unreliable lastmod" pattern the resolver's own header says makes a search engine discard the signal. Binding: (1) **any build-time derivation over the content collection — lastmod, feeds, related rails, counts, JSON-LD — reads only files whose frontmatter is `approved: true`**; a held file is invisible to every consumer-facing surface, not just to routing; (2) the fix is proved per #35 — *bite:* a scratch commit touching a held file must move **no** live date; *control:* a scratch commit touching an approved file must move exactly the dates it should; (3) the held-leak sweep gains a second assertion beside its slug check: **no `<lastmod>` in the sitemap is newer than the newest commit touching an approved file or a chrome file** — a date is a leak as surely as a slug. Sixth member of the enumeration family (*a green check is scoped to what it enumerates*): the slug sweep could not see a date. Forward question carried with it, deliberately not answered today: the 09-04 deploy moved all 82 dates for a `Base.astro` change that altered the served output of exactly one page (the English home's canonical) — the resolver derives *change* from **source provenance**, while the truth of "did this page change" lives in the **served bytes**, which only the deploy pipeline sees; an output-bounded lastmod (per-URL content hash across deploys) is the honest instrument, and it is a design question for the Web Developer, not a defect.

- **In wave mode the Verifier's verdict follows each pair's banking within the same week — verification is never deferred to the wave gate (codified 2026-09-06, weekly review).** The rule already existed in two places — *no piece flips without a Verifier verdict on file* and *drafting may not run more than three pieces ahead of the last verdict* (2026-07-12) — and the Verifier's own charter says *verification does not compress*. Edition 05 reached **three banked pairs and zero verification verdicts** (Zambia 08-27, Sierra Leone 08-30, Sudan 09-04) without any run naming it: the Editor's five-test *pair* verdicts and the Arabic Editor's gates were on file, and the 09-04 pair verdict's own note — "when the wave's verification pass runs" — shows the team had quietly re-scheduled verification to the end of the wave, in a batch, which is the one shape the Verifier persona was hired to refuse. The ≤3 ceiling was reached, not breached; the fourth draft (slot #3) would have breached it. Binding: (1) **the edition status memo (`/content-drafts/_EDITION_NN_STATUS.md`) carries the wave ledger from the first banked pair** — drafted / AR / pair verdict / **verification** / still / og card per slug — and the daily brief's pipeline line reads from it; (2) **a banked pair without a `<date>-<slug>-verification.md` seven days after banking is a P1 in the brief**, named in the first line of the Content function; (3) **the Verifier's verdict is scheduled the run after the pair verdict**, one per run, in banking order, and runs *in parallel* with the next piece's drafting — the ceiling is what makes the parallelism safe, and the ceiling is only real if the verdicts actually land. The wave gate is operational (Editor pair verdict + Verifier verdict + Arabic gate + still + og card + publish gate in writing → the Manager flips); what the founder owns is the edition's **scope**, never its approvals.

- **Founder-push availability — the standing question, answered by behaviour (2026-09-06 addendum to the 08-30 rule).** The 08-30 review asked the founder once: daily pushes as designed, or a formalized weekly window? He did not answer in words and did not need to: two blocks were staged this week and both landed within a day (08-31 staged → pushed 09-02 13:39; 09-03 staged → pushed 09-04 10:28), each with the `workflow`-scope PAT the commits required. - **The blind-spot question is a required written output of every QA pass, not a good habit (codified 2026-08-23).** The 08-18 defect — 83 days of share cards that resolved perfectly and rendered nowhere — was not stumbled into. It was found because the 08-17 log **wrote down a forward question**: *the sweeps check that a link resolves and that a page is reachable; neither checks that the thing at the other end is usable by the consumer that fetches it.* Asked deliberately the next morning, it failed on first contact. That is three findings in three days from one practice, and the practice was never written down — it happened because one run thought to do it. Binding: **every QA log ends with a named next surface** — one sentence answering *what can today's sweep not structurally see?* — and **the following run tests it before adding anything new.** A QA log that ends green with no forward question is incomplete, the same way an assertion that finds nothing to check has failed rather than passed (08-16 silent-pass trap). **The surface named and still owed, carried from 2026-08-18: the feeds.** Both are well-formed and serve 38 items each, and *nothing has ever verified that an item renders legibly in an actual reader, that Arabic items carry their direction, or that the links resolve from outside our own origin* — which is the whole point of a feed, and the exact shape of the og:image defect one surface over.

- **The annotation and the sentence are written from the same OPEN register — the non-numeric defect class (codified 2026-09-13, weekly review).** Edition 05's first three verification verdicts landed on three consecutive days and returned **six findings, not one of which was a number** — on three pieces, by three drafters, including Sierra Leone, the most figure-dense piece this publication has ever shipped, which passed every numeric test the operation owns. Our verification toolkit is entirely numeric (numeral-multiset comparison, one-sided-figure grep, prohibited-figure grep, the eight trace axes, #27's two channels) and **all six were invisible to all of it**; one of them was invisible *precisely because the correct number was absent*, and a check that compares the numbers present cannot see a year nobody wrote. Six for six is not luck, it is a location: the numbers are hard now and the errors have moved into the prose. **The binding shape comes from the repeat.** Twice in two days — Sierra Leone item 2 (*planned* launch) and Sudan item 2 (the *2018* laureate year announced in 2019) — the hedge was carried **correctly in `sources[]` in both languages** and **dropped from both bodies**. Two pieces, two drafters, one identical shape: that is a property of the workflow, not a slip by a writer, and the mechanism is visible once named — the `sources[]` annotation is composed *with the register open*, because it is a citation; the body sentence is composed afterwards **from memory of the annotation**, because it is prose, and the hedge, the noun, the date and the setting are exactly what memory smooths. Binding from this week: (1) **a load-bearing sentence is composed with its register open in front of the drafter, never from the annotation** — if the annotation had to be consulted to write the sentence, the source is re-opened instead; (2) **the hand-off to the Editor carries an `annotation == sentence` line for every source the piece leans on** — the drafter states, per source, that the hedge, the noun, the date and the setting in the body match what `sources[]` says about the same register, and a hand-off missing that line is returned unread (same teeth as the dek/title cap, 2026-07-27); (3) **the Verifier's trace gains four non-numeric rows beside the eight axes — noun (#45), quotation (#46), clock (#46), description-date (#47)** — each failed exactly like an untraced figure; (4) **the piece is read once against its own `sources[]` before the pair verdict**, in both languages, asking only *does the body say about this register what the citation says about it?* The forward surface is named so it is not forgotten: **the attribution verb** — *said · announced · confirmed · found · estimates* each promise a different register (#43's hierarchy applied to our own verbs) and nothing checks them.

- **A hand-run assertion is a habit, not a gate — wire it or state why it is out (codified 2026-09-13, weekly review).** The operation owns twelve standing assertions. Until today **seven** ran in CI and five ran only when a human remembered them — and the five were not the harmless ones. `qa_a11y_lang` bit on first contact with **471** chrome strings served under a language they were not written in, including *Skip to content* in English on all 40 Arabic pages, the first thing a screen reader announces; `qa_ar_language` bit with **235** Arabic-page fields printing English. Both have read clean on every hand-run since, which is exactly the condition under which a check quietly stops being run: **a green check that costs a human's attention is paid for out of the runs that have least of it — and those are the runs that ship the defect.** The 09-11 daily proved the class rather than the instance: `qa_jsonld` had existed since 08-29, ran by hand, was never in CI, and when it was finally extended and wired it immediately found **228 dangling references across all 76 article pages, standing for 19 days**. Binding: (1) **an assertion that reads only `web/dist` is wired into the CI build job in the same commit that proves it** — there is no intermediate state where it "runs in the daily"; (2) **an assertion kept out of CI carries its reason in the workflow file, at the point where the others are listed** — `qa_live_drift` reads the ORIGIN (the `verify` job's byte-compare is strictly stronger) and `qa_sources_alive` reads third-party hosts (someone else's 404 is not our build's failure); an assertion with no stated reason is simply unwired; (3) **the weekly review counts the gates and prints the ratio** — *N of M assertions gate the deploy* — because a count nobody prints is a count nobody notices drifting. Action of record: `qa_a11y_lang`, `qa_ar_language` and `qa_consumer_surface` wired today, each proved both ways per #35 before landing (control exit 0 on the real 82-page build; bite exit 1 on an Arabic string injected under `lang="en"`, on a Latin country name injected into Arabic chrome, and on an `og:image` reverted to SVG). **10 of 12 now gate the deploy, and the 2 that do not say why in the file.** Same family as every enumeration rule above, one turn further out: those asked *what can this check not see?* — this one asks **which of our checks does nothing at all unless somebody remembers it?**

- **A bite is injected against the SERVED shape, and an assertion must not be able to read its answer off the field it supplements (codified 2026-09-14).** Two traps caught inside one hour while proving `qa_geo_fields` per #35, both of which would have produced a check that passes forever. **(1)** The first bite — strip the rendered list line from a built page — **did not bite**. The injection regex was written against the source (`<p>Measured ·`) while Astro serves `<p data-astro-cid-…>Measured ·`; the check was fine and the *proof* was broken, which is the more dangerous of the two because it reads as a green. A bite that fails to change the artefact is a failed experiment, not a passing control: **assert that the injection changed the file before running the check on it.** **(2)** The check's first draft searched the whole marginalia block for each country name. The primary `country` is printed on the line *above* the list, so a completely unrendered list would still have reported that name as present — **the field the assertion exists to supplement was masking the assertion**. Rewritten to read the list line itself. Generalised: *where does the string I am looking for also legitimately appear?* — an assertion scoped wider than the thing it checks will find the right string for the wrong reason, which is the 09-11 lesson (a check that dereferences documents cannot see a broken reference inside one) restated on the input side. Both belong beside #35: **proving an assertion both ways means proving the bite as carefully as the control.**

- **A headline's superlative is read in the body BEFORE drafting, not before verification (ruling #49, codified 2026-09-14).** A superlative carries two scopes — the ruler it is measured on and the horizon it is measured within — and the bounding clause is the one a headline cuts, because it is the one that reads like qualification. While confirming a date for Edition 05's slot 3, a **first-party** register surfaced under the headline *« Le PASEC 2024 sera la dernière évaluation internationale »*; the bound (*before 2030, the end point of SDG 4*) sits in the next sentence, the same owner's February 2026 register names a **PASEC 2028** cycle, and the interview is dated **January 2023**. Taken as printed it would have inverted the piece's spine. Binding: **when a headline's superlative would change a piece's argument, the body is opened during recon** — this one would have survived to the verdict and been caught there, which is the wrong margin to work on; and **a superlative quoted from a source is quoted with its bounding clause or paraphrased with the bound restored.** Extends #29 (*a superlative is a figure*) from aggregators to owners, and joins the non-numeric family: it contains no number at all, and its unit is a date.

- **A cloud run can push, and a cloud run cannot publish — plan the day accordingly (codified 2026-09-14, run 2).** The cutover this morning removed the founder from the *start* of the day and from the push. It did not remove him from the deploy, and the first autonomous run found out by trying: the push to `main` succeeded and **started no workflow run at all**, because a push authenticated with the Actions token does not trigger other workflows (GitHub's anti-recursion rule); and `gh workflow run astro-pages.yml` returns **403 Resource not accessible by integration**, because the daily workflow grants `actions: read`. General form, and the reason it is worth a rule rather than a note: **an autonomy that removes a human from the work but not from the publication has moved the dependency, not removed it** — and moved it somewhere less visible, from a paste he was asked for to a click nobody mentions.

- **A register consolidated weekly against a daily filing rate drifts by construction — so the RANGE is reconciled at the point of filing, and only the prose waits for Sunday (codified 2026-09-20, weekly review).** The guidebook's ruling register arrived at this review reading `#1–#48` while **ten** rulings, #49 through #58, sat on disk, filed by the runs that earned them, cited by number in commit subjects, briefs, verdicts and the edition ledger. The weekly skill already warns that this register "has drifted three weeks running, always in the same direction." It has, and the direction is not carelessness: **the drift scales with the run rate.** A consolidation cadence designed around four rulings a week is one week behind at ten, and the run rate doubled the moment the operation moved to the cloud — nine runs in seven days this week against five in seven last. Escalating diligence does not fix a cadence mismatch; it just makes the same gap feel worse. Binding: (1) **the run that files a ruling updates the series-integrity range and the §3 heading in the same commit as the ruling file** — one line, two numbers, no prose, no judgment, and it is the *only* part of the register that must be current daily; (2) **the weekly consolidation writes the canonical one-liner, the family placement and the Section 1 row** — the work that genuinely needs a week's perspective — and reconciles the range it finds against the rows it can count; (3) **every section that carries a set gets a count line**, and a section without one gets one written at the next consolidation; (4) **the count is reconciled against its own rows, never against the previous week's count.** General form, and it applies well beyond this register: *a document maintained on a slower clock than the work it describes is not out of date by accident — it is out of date by design, and the fix is to move the cheapest part of the maintenance onto the faster clock.* The same defect stood in `CLAUDE.md` on the same morning, and cost more: it told every run that the operation owns **fourteen** assertions of which **13 gate the deploy**, when the true numbers were **21** and **19** — stale by seven assertions, in the one file every session is instructed to read first. Third instance of this shape (the CHARTER's "(7)" headcount, four additions out of date until 2026-08-16; the §3 families heading reading "three" while listing seven, since 2026-08-23). **A count in a heading is maintained by nobody unless somebody is named.**
