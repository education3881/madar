# Growth — the page every broken link lands on

**Filed:** 2026-09-09 · Growth (with the Web Developer) · daily growth action
**Shipped this run:** a branded, bilingual, `noindex` 404 at `/madar/404.html`

## The observation

Fetched from the live origin at 09:41 today, not assumed:

```
GET https://education3881.github.io/madar/articles/does-not-exist/   -> 404
```

The body is GitHub Pages' stock page. What a reader actually receives:

- **No Madār anything.** No wordmark, no palette, no typeface, no Arabic — on a
  publication whose whole claim is that it is made in two languages with neither
  subordinate to the other.
- **Four outbound links, none of them ours:** `help.github.com`,
  `githubstatus.com`, `twitter.com/githubstatus`, and a logo linking to `/` —
  which on a **project** site is `education3881.github.io`, the user root, **not
  this publication**. So the one page guaranteed to be reached by every broken
  inbound link sends the reader to GitHub and to X, and offers no route back
  into Madār at all.
- It has been that way since the first publish on **2026-05-25** — 107 days.

## Why this is a growth action and not a polish item

The CHARTER's growth rule is **return, not reach**. Every reader who lands here
has already done the expensive part: they clicked. The link was wrong — a
mistyped slug, a share truncated by a messenger, a URL that outlived a rename,
a crawler following something stale — and the reader is, at that instant,
one link away from the publication and receiving zero.

Three specific losses, in the order they matter:

1. **The Arabic reader is invisible to this page.** Every `/ar/` path that fails
   serves an English GitHub error. For a bilingual publication that is not a
   missing feature, it is a statement.
2. **Zero paths back in.** A dead end is a lost session; a dead end with a door
   is a reader who reads something else.
3. **Two competitors' logos on our worst page.** GitHub and X get the only
   branded surface in the whole experience.

And the timing is not neutral. The site has **0 of 82 URLs indexed** (recorded
08-25) and the operation is deciding whether to switch IndexNow on. The first
crawler to arrive in volume is also the first agent to generate 404s in volume,
by trying paths that no longer exist and paths it inferred. Fixing the landing
before inviting the traffic is the cheap order.

## What shipped

`web/src/pages/404.astro` — one page, both languages side by side, in the site's
own chrome:

- **Bilingual by necessity, not symmetry.** GitHub Pages serves **one** 404 for
  the entire project site, including every `/ar/` path, so the page cannot know
  which language its reader came for. It therefore says the same thing twice, in
  full, and offers both front doors rather than guessing and being wrong for
  half the audience. The Arabic side is composed, not translated — including
  the numeral: **٤٠٤**.
- **Five ways back in:** English home, all editions, About; Arabic home, all
  editions. (No Arabic About link — there is no Arabic About page yet, and a
  link to an intention is a defect, not a placeholder. RUNBOOK, 08-16.)
- **`noindex, follow`** — indexable would offer a crawler an unbounded set of
  distinct URLs sharing one body. `follow` so the links out are still walked.
- **No canonical, no `og:url`** — a page served under every wrong URL on the
  site has no address of its own, and the derived canonical pointed at
  `/madar/404/`, which does not exist.
- **Not in the sitemap**, and on the reachability allowlist as the one page whose
  orphanhood is the design.

## What this does not do, said plainly

It does not bring anyone. It is a retention fix on a surface we cannot count:
the site carries **no third-party tracker by design**, so the number of 404s
served is unknown and will stay unknown. No figure is claimed here and none
should be inferred. What changed is the *shape* of the failure — from a dead end
that advertises somebody else, to a page in our own voice with five doors in it.
