## 1. P0 — the 09-17 deploy was RED, and the cause was our own instrument

Run `35209579023`, dispatched by the daily workflow's own publish step at 10:16 on 09-17,
**failed**. The build was clean, twelve assertions passed, and the thirteenth stopped it:

```
DEFECT: https://education3881.github.io/madar/valence/ lastmod 2026-09-17T10:14:26+00:00
        is ABOVE the ceiling 2026-09-15T09:32:02+00:00 — no approved or chrome file is that new
qa_lastmod: 1 defect(s) across 120 URL(s)
```

**The date was truthful and the check was wrong.** Commit `bd3c48e` edited
`web/public/valence/index.html` — #55's Arabic fix applied to the one page the build does
not style — so the page's served bytes genuinely changed at 10:14:26 and the resolver
emitted the real commit time. `qa_lastmod`'s ceiling is
`max(newest approved content commit, newest chrome commit)`, and `web/public` is in
neither list. The check had never had anything true to say about that URL.

Reproduced locally on the first attempt; the fix and its four-way proof are recorded under
**ruling #56**, origin case B. In short: the resolver has **three** branches and the check
modelled **two**, so the ceiling is now derived **per URL** from the resolver's own rule,
with the static-page set discovered from `web/public/**/index.html` rather than named —
a second static page inherits the bound with nobody remembering to add it (#36).

**Not fixed by widening the ceiling to include `web/public`**, which was the obvious
one-line repair and would have been a regression: held pieces' stills and og cards live
under `web/public/stills` and `web/public/og`, so a ceiling that rose with them would rise
on every commit touching a held draft — re-opening the exact leak (`9886987`, `642fef2`)
`qa_lastmod` was written to close. **Never widen a bound to admit an honest case.**

### Proof, per #35 and the 09-14 discipline — every injection verified to have changed the artefact before the check read it

| | injection | result |
|---|---|---|
| control | none — the real 120-URL build | **PASS**, exit 0 |
| bite B | an article lastmod set to 2099 | **2 defects** (above ceiling; in the future) — the original assertion intact |
| bite C | one `<lastmod>` stripped | **1 defect** — absence still fails |
| bite D | the `/valence/` `<url>` block removed from the sitemap | **exit 2** — "its ceiling checked nothing"; new machinery that matches nothing is a failure, not a pass |
| **bite A** | scratch chrome commit raising the global ceiling, then `/valence/` dated **between** its own file's commit and that ceiling | **old check PASS · new check DEFECT** |

Bite A is the one that matters, because it isolates the change. It is a date the single
global ceiling **accepted in silence** — which is the half of this defect nobody had
noticed: under one ceiling, `/valence/`'s date was only ever tested for being too *large*.
The URL the check failed the deploy on is the URL it had never actually checked. **The fix
is a strengthening, not a loosening.** The scratch commit was reverted with
`git reset --soft` so the working tree kept the uncommitted fix; `qa_dist_input` then
caught the reverted file's mtime being newer than the build and refused to let the other
assertions be trusted — #52 working on the residue of our own experiment, unprompted.

**Named limit, carried rather than implied:** a ceiling bounds from **above** only. A
`<lastmod>` that is too *old* — a page that changed and reports that it did not — passes
every branch, and that is the direction a crawler punishes. The per-URL ceiling narrows
the gap; it does not close it. Written into the tool's own head.

## 2. The 09-17 forward question, tested before anything new was added — and the answer was NO

The rule (08-23) is that the next run tests the named surface first. **Today is the first
time testing one returned a negative, and that is the practice paying for itself.**

The candidate oracle, as written on 09-17: *measure the advance width of a known Arabic
string against the same string with `letter-spacing` forced; if the two widths are
identical the font is not shaping.* Measured on the real Arabic home page, in the page's
own inherited font:

```
case                  natural     zwnj   ratio     tracked   ratio    feat-off   ratio
بببب                    28.88    66.69   0.433       28.88   1.000       66.67   0.433
العربية                 35.61    68.78   0.518       35.61   1.000       68.73   0.518
لا  (ligature)          11.56    14.77   0.783       11.56   1.000       14.77   0.783
مدار                    26.58    27.34   0.972       26.58   1.000       27.33   0.973
```

**The `tracked` column is 1.000 on every string, on a perfectly healthy page.** The reason
is #55's own fix: `:lang(ar){letter-spacing:normal!important}` means tracking can no
longer be forced onto an Arabic element here at all. The proposed check would read its own
failure condition on a correct build. And the inference was unsound regardless — forcing
tracking widens shaped and unshaped runs alike, so it measures tracking, not joining.
**A rule and the instrument proposed to succeed it were written hours apart in the same
log and are incompatible** (recorded as an amendment inside #56).

**The oracle that works is in the `zwnj` column.** Compare a run against itself with
U+200C ZERO WIDTH NON-JOINER between every letter pair: the known-unshaped case by
construction, in the same font, on the same page. The control the 09-17 log said we did
not have (a deliberately missing font family) turns out not to be needed.

Third finding from the same bench, recorded so it is not rediscovered: **`مدار` is a bad
probe.** Dal and alef do not join leftward, so a correctly shaped `مدار` is 3% narrower
than a broken one — 0.972 — where `بببب` is 0.433. The probe string is chosen for joining
density, never for being ours.

## 3. Standing assertion 18 — `qa_arabic_joining.py`, landed and gated

Two halves, because there are two defects. **FONT**: a fixed joining-dense probe in the
page's own inherited Arabic face, fires when the resolved font does not shape. **SERVED**:
the page's longest real Arabic run, fires when our own content or CSS breaks joining while
the font is fine. Four targets (AR home, AR article, EN home, VALENCE).

**It bit twice on its own machinery before it bit on anything else, and both are worth the
paragraph:**

1. **First control run reported 2 defects on a perfect build.** It had selected the
   **JSON-LD block** as "the longest Arabic-bearing element" — 4,000 characters of Latin
   schema.org with the publication's Arabic name inside — and measured a ratio of 0.998.
   The 2026-09-14 masking trap exactly: a selection rule scoped wider than the thing it
   selects finds the right string for the wrong reason. Fixed by skipping non-rendered
   elements and selecting on **Arabic character count with an 80% density floor**.
2. **Then the ZWNJ bite fired for the wrong reason** — "no Arabic run long enough to
   measure" instead of "this run did not join" — because the density floor I had just
   added counted the injected ZWNJs in its denominator. **A de-joined run is by definition
   a run stuffed with invisible non-Arabic characters**, so the filter made the check
   structurally unable to select the one text it exists to catch: a check that could not
   run, wearing the costume of a check that found something. Zero-width format characters
   are now struck from the denominator and left in the measured string.
3. And the probe's own construction was wrong once: it built the measurement span from the
   **`font:` shorthand**, which resets `font-feature-settings`, `font-variant-ligatures`
   and `font-kerning` — the exact properties a shaping defect lives in. Caught before bite
   A was run, not after. Copies the longhands now.

**Proof, four ways, each injection verified to have changed the artefact first:**

| | injection | result |
|---|---|---|
| control | none | **CLEAN** — 12 runs measured; worst font probe **0.630** (threshold 0.75), worst served run **0.730** (threshold 0.90) |
| bite A | `font-feature-settings:"init" 0,"medi" 0,"fina" 0,…` appended to the built CSS | **9 defects**, both halves, ratios **1.000** — VALENCE silent, because its CSS is its own file the injection did not touch, which is the count being its own proof again |
| bite B | 1,768 ZWNJ injected into `/ar/`'s served text only | **1 defect**, ratio 0.961, **SERVED half only — the FONT half stayed clean**, proving the halves independent |
| bite C | `/ar/` stripped of Arabic, CSS untouched and correct | **floor fails** — 0 elements against a floor of 20; a check with nothing to measure has failed, not passed |

Margins are now **printed on every clean run** rather than merely satisfied, because a
count nobody prints is a count nobody notices drifting.

**Wired into `postbuild` in the same commit that proved it** (09-13 rule), because this
identity still cannot write `.github/workflows/**` (09-14 rule, clause 4).
**16 of 18 standing assertions now gate the deploy**, and the 2 that do not say why in the
workflow file: `qa_live_drift` reads the origin (the `verify` job's byte-compare is
strictly stronger) and `qa_sources_alive` reads third-party hosts.

**Honest limit, in the tool's head and not only here.** Amiri is fetched from
`fonts.googleapis.com` at read time. This assertion measures the font **this runner**
resolved, not the reader's. It gates every shaping defect that is a property of our own
bytes — which is the whole of what we have ever shipped — and nothing else. See the
Growth audit filed today.

## 6. Forward question for the next run, per the 08-23 rule

**Named limit first, because it is the sharper one and it is mine:** `qa_lastmod` bounds
dates from **above** only. Nothing in this operation can see a `<lastmod>` that is too
**old** — a page whose bytes changed and whose date says they did not. That is the
direction that actually costs us crawl attention, and the 09-06 review already named the
honest instrument for it and called it a design question: an **output-bounded lastmod**, a
per-URL content hash compared across deploys, which only the deploy pipeline can see. It
has been a design question for twelve days. The `verify` job **already downloads the
published artifact and byte-compares it against the origin** — it is holding both sides of
that comparison in its hands and throwing them away. The next run should look at whether
`verify` can emit a per-URL hash manifest, because if it can, the hard part is done.

**Second surface, carried unanswered from 09-16 and 09-17 and now owed for three runs:**
nothing compares the assertions' counts to one another. Pages built · sitemap `<loc>` ·
reachability · jsonld · a11y · hreflang · assertion 17's 326 elements · assertion 18's 12
runs — eight numbers, already emitted by eight instruments, that must agree within known
offsets and have never been read together. Today added a ninth and did not read it against
the rest either. **A note discovered while writing assertion 18, which is exactly the kind
of thing this cross-check exists to surface:** assertion 17 counts `<script>` JSON-LD
blocks among its "Arabic-bearing elements", so its **326** is inflated against assertion
18's element census, and a `letter-spacing` on a `<script>` tag — which no reader could
see — would be reported as a defect. Harmless today. Exactly the sort of quiet
disagreement between two instruments that nobody is looking for.
