## 2. Standing assertion 19 — `qa_census.py`, landed and gated

It derives every population independently from `dist` and the content collection, asserts
the set relations **by name**, and then reads each instrument's **printed** number against
the population that instrument declares it means. Seventeen numbers from eleven
instruments.

It reads stdout on purpose: the number a tool *prints* is what a human, a log and the next
run consume, and a tool that computes correctly and prints a mislabelled number is a real
defect class. **It found one immediately** — see §3.

**Proved both ways per #35, every injection verified to have changed the artefact before
the check read it:**

| | injection | result |
|---|---|---|
| control | none — the real 121-page / 120-URL build | **CLEAN**, 17 numbers, every relation held |
| bite 1 | an extra page written into `dist`, absent from the sitemap (the 08-17 orphan shape) | **1 defect**, **naming the page**. The count rows all stay green, because the census derives expectations from the dist it reads — the set relation is the half that bites, by design |
| **bite 2** | one `<loc>` swapped for a URL the build does not serve | **3 defects** — and **served 121, sitemap 120, every cardinality identical to the clean build.** Names both the URL that appeared and the one that vanished. **This is the bite the file exists for** |
| bite 3 | `qa_ar_language` made to print 58 for the 59 pages it checks, behaviour unchanged | **1 defect**, naming tool, population, expected and read |
| bite 4 | a pattern edited to match nothing | **1 defect**, naming the tool whose line it could not read, rather than comparing the 16 rows it did find |
| gate | `NOT_ROUTED` made to declare a page the build does not serve, then `npm run build` | **exit 1** — the assertion actually fails the build, proved rather than assumed |

**And the result worth more than any of them.** The *first* attempt at bite 3 used a regex
that did not match the tool's print statement, so the injection never happened — and the
census printed **CLEAN**, exactly as it does on a healthy build. A bite that fails to change
the artefact is indistinguishable from a passing control (the 09-14 rule). The `assert`
that the file changed is what caught it. **Second consecutive run in which that discipline
has paid.**

**Wired into `postbuild` in the same commit that proved it** (09-13 rule), because this
identity still cannot write `.github/workflows/**` (09-14 rule, clause 4).
**17 of 19 standing assertions now gate the deploy**, and the 2 that do not say why in the
workflow file: `qa_live_drift` reads the origin (the `verify` job's byte-compare is strictly
stronger) and `qa_sources_alive` reads third-party hosts.

## 3. Three defects the census found, all of them ours

**(a) `qa_dist_input` printed `120 built page(s)` for a dist containing 121.** It enumerated
`rglob("index.html")`, and the branded 404 is a built page that is not an index. Harmless to
the freshness test it exists for, and wrong in the log, which is where the number is
consumed. Corrected to `rglob("*.html")`; its non-vacuity floor is stronger for it.

**(b) Two of eleven siblings crash when called from `web/` — which is where `postbuild`
runs.** `qa_body_links` and `qa_held_assets` resolve the content collection as the relative
path `web/src/content`, so from `web/` they look for `web/web/src/content` and exit 2 and 1
respectively. Latent for weeks, because the workflow has always invoked them from the
repository root; the census was the first caller to invoke them from anywhere else and
found it on its first postbuild run. Fixed in the **caller**: the census runs every sibling
from the repository root explicitly. **#16 turned around and pointed at the caller** — an
assertion's answer must not depend on who called it.

**(c) The census failed on itself, in production, on the first build after today's draft
landed.** It derived "held slugs" as `len(held files) // 2`, because every piece in this
corpus has always had an Arabic twin. Egypt is English-only until its Arabic is composed:
nine held files are **five** held slugs, and the halving said four. `qa_held_assets` was
right and the new instrument was wrong. Fixed by counting distinct stems. **An invariant
that has held for every case so far is still an assumption, and dividing by it is how an
assumption gets welded into an instrument** — corollary 3 of the ruling, earned by the
ruling's own file within an hour of its being written.

## 4. Assertion 17's element census was inflated, and is no longer

The 09-18 log predicted this and could not measure it: `qa_arabic_shaping` selected
`querySelectorAll('*')` and counted every element with Arabic in its own text, **including
elements no reader ever sees laid out by our CSS**. Measured today two independent ways —
a static parse of the seven target pages and the browser itself — which agree exactly:

**326 → 310.** The 16 excluded are **5 JSON-LD `<script>` blocks** (4,000 characters of
schema.org carrying the publication's Arabic name and its headlines), **5 HTML `<title>`**
and **6 SVG `<title>`** — the hero stills' accessible names, tooltips, never painted. The
SVG `<text>` elements, which are the stills' visible captions, stay.

Two costs paid by the old number: it was incomparable with assertion 18's census, and a
`letter-spacing` landing on `head title` would have been reported as a defect **on a page no
reader could tell had changed.**

**Proved by isolation, and the first bite failed, which is the instructive part.** A plain
`p,h2,a{letter-spacing:.05em!important}` injection **did not bite** — because #55's own fix
(`:lang(ar){letter-spacing:normal!important}`) outranks a type selector, so the injection
never reached an Arabic element. That is the same wall the 09-18 run hit from the other
direction, and it is worth knowing in its own right: **since #55, a tracking defect in our
own stylesheet would have to be written deliberately specific to land.** Re-injected above
that specificity:

| | injection | old version | new version |
|---|---|---|---|
| A | `html:lang(ar) p, html:lang(ar) h2` tracked | fires | **fires** — the rendered half is untouched |
| B | `html:lang(ar) title, html:lang(ar) script` tracked | **11 defects**, on `<title>` and JSON-LD | **silent** — correctly |
| control | none | CLEAN 326 | **CLEAN 310** |

## 7. Forward question for the next run, per the 08-23 rule

**The surface named on 09-18 and still owed, because today took the other one:** `qa_lastmod`
bounds dates from **above** only. Nothing this operation owns can see a `<lastmod>` that is
too **old** — a page whose bytes changed and whose date says they did not — and that is the
direction a crawler punishes. The honest instrument was named on 09-06 and has been a design
question for thirteen days: an **output-bounded lastmod**, a per-URL content hash compared
across deploys. **The `verify` job already downloads the published artifact and byte-compares
it against the origin** — it holds both sides of that comparison and throws them away.

**And today makes the design tractable in a way the 09-18 note did not see.** The obstacle
has always been *where a manifest would live*: this identity cannot write
`.github/workflows/**`, and a workflow artifact needs plumbing and permissions. It does not
need either. **The build can emit the manifest into `dist` itself** — a per-URL content hash
at a stable served URL — so the *next* build fetches the previous deploy's manifest from the
origin, exactly as `qa_live_drift` already fetches the origin today, and compares. No
workflow edit, no artifact retention, no new permission. The manifest is published by the
same mechanism it measures, which is also its own weakness and should be said: a manifest
served from the site it describes cannot detect a deploy that failed to publish anything at
all — but the `verify` job's byte-compare already covers precisely that case. **The next run
should build it.**

**The new surface this run opens, named so it is not lost:** assertion 19 compares eleven
instruments' page populations and **does not compare the two element censuses** (17's 310
Arabic-bearing elements, 18's 12 measured runs) — deliberately, because they need a browser
and their population is elements. But today's §4 shows an element census can be inflated by
5% for a month without anything noticing, and the only reason it was caught is that a human
wrote the suspicion down. **Nothing structurally compares 17's element set to 18's.**
