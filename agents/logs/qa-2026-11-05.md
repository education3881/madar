## 2 · Item 31 is CLOSED at 15 days — standing assertion 42, `qa_prior_publication`

**What the row asked:** every instrument runs inside the agent step and the deploy runs after that step
ends, so **no run has ever observed its own publication.** #71 answers it in prose — *every brief
carries the previous run's deploy ID, its conclusion and a `qa_live_drift` result* — and **nothing
fails when that sentence is not honoured.**

**Shipped:** `agents/tools/qa_prior_publication.py`, wired into `postbuild` in the same commit that
proves it (09-13: *an assertion that reads only the tree is wired in the commit that proves it*).

* **`--observe` (network, gates nothing).** Asks the Actions API for the last `astro-pages.yml` runs,
  takes the most recent and the most recent **successful** one, reads the tip of `origin/main`, and
  computes the **strand**: the commits on `main` that no successful deploy has carried. If the API does
  not answer, **no row is written** and the exit is 2 — a row that records a failure because we were
  throttled is an observation about us (#111). Register: `agents/stats/publication-observations.jsonl`.
* **`--check` (offline, deterministic, GATED).** Five limbs: schema; **provenance** — every row's
  `strand_len` must equal `git rev-list --count <deployed>..<tip>`, so a row that cannot be
  re-derived from this repository's own history is a fabricated observation; **the newest row must be
  verifiable**, which is the non-vacuity guard *derived* rather than counted (item 67 — the guard is
  *the newest row*, not *N rows*); **monotonicity** — the deployed SHA never walks backwards; and
  **the duty**, limb 5.

**Limb 5 is the limb that closes the item rather than merely answering it.** Limbs 1–4 all stay green
for a run that observes nothing at all: the rows a previous run wrote remain well-formed and
re-derivable forever, which is **item 31's own defect one level out — a register whose upkeep is
checked only by the next run's goodwill.** So inside the **daily** run the register must carry a row
written by **this** `GITHUB_RUN_ID`, and a daily run that builds without observing reds its own build
with the command it should have run. In the **deploy** job the limb prints SKIPPED with its reason,
because the deploy owes no observation and must never red for the daily run's silence.

**PRINTED AND NOT ASSERTED: the strand length and the prior deploy's conclusion. The reason is not
#93's floor-above-reality, and it is worth stating in its own words:**

> **An assertion whose only repair path runs through the artefact it blocks cannot be gated.** A red
> prior deploy is repaired by pushing a commit; a push is made by a run whose build is green; so a gate
> that reds on a red prior deploy forbids the one action that would clear it. Had this gate existed on
> 2026-10-21 with the strand asserted, it would have been unable to build, unable to push, and
> therefore unable to recover the 10-20 strand — **converting a two-day publication gap into a
> permanent one.**
