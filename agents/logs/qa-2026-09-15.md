## 1. The forward question, answered before anything new was added

The 09-14 log named it: **nothing this operation owns has ever checked that a page
RENDERS.** Thirteen assertions read structure — a thing is present, resolves,
parses, matches, agrees — and not one had looked at a pixel, while three
render-class defects sat in the record, every one of them found by a human
happening to look:

| date | defect | found by |
|---|---|---|
| 2026-08-16 | the daily brief rendered edge-to-edge for two days | someone opening one |
| 2026-08-18 | the Arabic wordmark's letter-joins broke on the VALENCE card | someone opening a PNG |
| 2026-09-14 | an undefined CSS token put a country label in the wrong colour on 76 pages | the eye, after thirteen green checks |

**`agents/tools/qa_render.py` lands as standing assertion 14.** It rasterises four
pages and one share card with headless Chrome and asserts **properties of the
rendering, never its identity** — a screenshot diff fails on every legitimate
edit, which is why this was a question and not a task. Three properties, each
taken from a defect that has actually bitten:

- **P1 not blank** — ink coverage above a floor.
- **P2 legible** — ink-dark pixels present on a light ground (the white-on-white case).
- **P3 accent present** — the design system's kiln-orange reaches the raster. An
  undefined token evaporates into the inherited ink: structurally invisible,
  visibly wrong. This is the 09-14 class, instrumented.

PNG decoding is pure standard library, including the palette format the share
cards use. The browser is **the first dependency the QA toolkit has ever taken**,
and if none is found the tool exits 1 rather than skipping — a check that silently
does not run is a green light wired to nothing (09-13).

### Proved four ways (#35, and the 09-14 addendum on proving the bite)

Every injection was verified to have **changed the artefact** before the check was
run on it — a bite that does not change the file reads exactly like a passing
control.

| | what was done | result |
|---|---|---|
| control | the real 120-page build | **exit 0**, silent on all five targets |
| bite A | `--color-orange` rewritten to the ink value in the served CSS | **exit 1** — P3 on all four pages |
| bite B | body text set to the paper colour in the served CSS | **exit 1** — P1 and P2 on three targets |
| bite C | one page's `<body>` emptied in the served HTML | **exit 1** — P1, P2 and P3 on that page |

### And bite A produced today's ruling

On the two **article** pages the accent count fell **674 → 0** and **629 → 0**. On
the two **home** pages it barely moved: **949 → 900** and **849 → 817**. The hero
still carries its own kiln-orange as an SVG literal, does not read the token, and
sat inside the region being measured — so a floor set there **would have passed
forever with the accent entirely dead.** That is the 09-14 masking trap one
artefact over instead of one field over, and it is corollary 5 of ruling #51 filed
today.

P3 is now scoped per target, and each scope is the one **proved able to fail**: the
chrome band on the home pages (**49 → 0** and **32 → 0** under the same bite), the
whole page on the article pages, where the chrome band carries no accent at all.
Recorded in the tool at the point of decision, not only here.

**Gating:** wired into `web/package.json` as a second `postbuild` step beside

## 5. Forward question (required per the 08-23 ruling) — for the 2026-09-16 run, before anything new

`qa_render` proves a page draws ink, keeps its ground and carries its accent. It
cannot yet see **whether Arabic renders as Arabic** — joined script rather than
disconnected letterforms or tofu — and that is the one render defect this
operation has actually shipped: the VALENCE share card's broken letter-joins on
2026-08-18, caused by a `letter-spacing` that is never applied to Arabic and
found by a human opening the PNG.

The obstacle is named so tomorrow does not spend the morning rediscovering it:
**joining has no stable pixel oracle.** Ink coverage cannot tell a joined word
from a broken one, and a glyph-level test needs a font-aware comparison we have no
way to make honestly. The candidate is therefore not a picture but a **computed
style** — *no rule that reaches an Arabic run may set `letter-spacing` to anything
but `normal`* — which needs either a driver we do not have (CDP, a dependency
larger than the one taken today) or a static read of the built CSS against the
selectors that reach `[lang="ar"]`, `[dir="rtl"]` and the Arabic font stack.
Decide which, then prove it against the **known-broken control**: the 08-18
VALENCE card, whose defect is on the record with a described appearance.

## 6. Addendum, after the push — the dispatch route, tested rather than assumed

The run pushed (`cc44be9 → 845578a`) and then tried to dispatch the deploy itself,
to check the 09-14 fix from the inside rather than from the workflow file:

```
gh workflow run astro-pages.yml --ref main
→ HTTP 403: Resource not accessible by integration
```

**And the daily workflow does declare `actions: write`.** That permission block
governs the job's `github.token`; the agent holds a narrower App installation token
— it can read workflow runs and push commits, and it cannot dispatch a workflow or
read `/user`. So the 09-14 design (dispatch from a workflow step, after the agent's
step ends, only when the origin actually moved) is not the better of two working
routes. **It is the only route**, and the permissions block in the workflow is not
evidence that the agent can do the thing it names.

Consequence, stated rather than glossed: **this run cannot observe its own deploy.**
It can confirm the dispatch was correctly asked for. The `verify` job byte-compares
the published artifact against the origin, so a failure lands in tomorrow's state
verification — which is the first thing tomorrow's run does anyway.
