## 1. The held-asset surface — the 09-08 forward question, answered and closed

**The question, as filed:** a held file contributes no page, no sitemap entry, no feed item
and (since 09-08) no date. *Nothing yet proves it contributes no bytes at all.*

**Measured first, decided second.** On this morning's pre-fix build:

| | |

| total size | ~48 KB (3 stills + 3 raster cards) |
| references from any served HTML or XML | **0** |

"Nothing links to them" was the argument for leaving them, and it is the **same wrong test**
that let SVG share cards resolve perfectly and render nowhere for 83 days (08-18). The right
test is *what can a stranger GET*. Every path is derivable from the slug pattern the
published articles advertise, so this was true on the live origin at 09:40 today, **fetched
rather than inferred**:

```
GET /madar/stills/2026-09-01-sudan-cant-wait-to-learn.svg   -> 200
GET /madar/articles/2026-09-01-sudan-cant-wait-to-learn/    -> 404
```

And the still is an SVG, so the fetch returns **readable text**:

> `<title>The Still · Sudan — the classroom that left home, and the returning arc</title>`

plus a 90-word `aria-label` describing the piece's central image. An edition that ships as
one gated wave was serving three unpublished pieces' subjects at guessable URLs.

**DECISION (Manager + Web Developer, in writing): WITHHOLD.** Ship-early's only benefit was
a smaller flip commit, and the flip commit is a one-line flag change either way — the assets
stay in `public/`, where the publish gate already checks for them, and are removed from
`dist` at the end of the build. Nothing about the gate changes; the bytes stop being served
a wave early.

**(a) The mechanism** — `src/lib/heldAssets.mjs`, an `astro:build:done` integration, derived
from the content collection rather than a hand-kept exclude list (RUNBOOK 06-07: anything
that must equal "the current set of held pieces" is generated or it is correct for one day).
It reads the hold through `heldContentFiles()`, **the same parser the lastmod resolver
uses**, exported for the purpose — two modules deciding independently what "held" means is
the drift defect one refactor away. Fail-loud: a held slug with no assets in `dist` throws,
because "nothing to remove" and "nothing was ever there" are different facts and only one is
fine. Slug matching is on the filename **stem**, not substring, so a future slug containing
a held slug is not swept away with it.

**(b) Standing assertion #12 — `qa_held_assets.py`**, the output-side twin, which does not
trust the mechanism. Asserts: no held slug appears as a filename stem anywhere in `dist`;
every held slug's assets are still present in `public/` (withholding is an omission from
the served output, never a deletion from the repo); and — the control — **every approved
slug's still and card ARE in `dist`**, so a sweep that deleted the whole `og/` directory
could not pass.

**(c) Proved both ways on real state (#35).**

## 2. The branded 404 (Growth's action, and the three defects it exposed)

See `agents/growth/2026-09-09-404-surface.md` for the audience argument. The QA record is
what building it *found*, all three caught by looking at the built output rather than by
trusting the page:

1. **`robots` was hardcoded** to `index, follow` on every page since launch. Correct while
   every page was one we wanted found; a 404 is served under an unbounded set of URLs, so
   indexing it offers a crawler infinitely many distinct URLs with one body. Added a
   `noindex` prop — opt-in, because the safe direction is that a page is indexable unless a
   human said otherwise.
2. **The canonical dereferenced to nothing.** Base derives the canonical from the served
   shape (the 09-03 fix), which for `404.html` produced `/madar/404/` — a directory route
   that does not exist and would itself 404. A canonical is a promise about where a document
   lives (#36); a promise that dereferences to nothing is worse than silence. `noindex` now
   suppresses both `canonical` and `og:url`, on the reasoning that a page with no address
   has no canonical address.
3. **Two CSS custom properties did not exist.** `--font-arabic-body` and `--color-accent`
   were invented at the keyboard; the tokens are `--font-arabic` and `--color-orange`. An
   undefined `var()` silently renders as nothing — the Arabic body would have fallen back to
   the browser default face and the link rules would have had no colour. Fixed, and swept:
   **84 built files, 69 custom properties used, every one resolving** except VALENCE's
   `--c`, which is set at runtime by `setProperty` and is therefore correct.

`qa_consumer_surface` and `qa_reachability` both **bit the new page on first contact** —
the first missing an og card, the second reporting it as an orphan. The og card is a real
fix (`/og/brand-card.png`). The orphan is not: **a 404 is reached by failure, never by a
link**, so it goes on the exemption list — and the exemption list is now itself asserted,
because an allowlist is where defects hide (08-09 flag-sweep inversion): exactly one entry,
it must exist in `dist`, and the reason is written beside it.

built cleanly, passed every one of the twelve standing assertions, and would have shipped

standing assertion gets ignored (#35).

**Named surface for 09-10: the design tokens are a contract nothing checks.** Candidate
assertion — every `var(--x)` in built CSS and inline styles resolves to a definition in the
built output *or* to a documented runtime setter. Beyond that sits the wider question this
one is a member of: the twelve assertions we own all check **structure** — that a thing is
present, resolves, parses, matches. **Nothing checks that a page renders.** The 08-18
Arabic wordmark joins were found by looking at a PNG; nothing has looked since.
