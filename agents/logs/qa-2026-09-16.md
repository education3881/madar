## 2b. `qa_render` ran — for the first time outside CI — and the desktop path can now do render work

`qa_render` landed yesterday as assertion 14 and has never run on this machine, because the sandbox ships no browser. It was refused again this morning, correctly and loudly. It was then **made to run**, without root:

```
pip install playwright --break-system-packages
python3 -m playwright install chromium            # NOT --with-deps; that needs sudo and fails
apt-get download libxdamage1 libxfixes3 libxrandr2 libxkbcommon0 libxcomposite1 \
                 libatk1.0-0 libatk-bridge2.0-0 libcups2 libpango-1.0-0 libcairo2 \
                 libasound2 libatspi2.0-0 libxext6 libnspr4 libnss3
for d in *.deb; do dpkg -x "$d" root; done        # unpack, do not install
export LD_LIBRARY_PATH=$PWD/root/usr/lib/aarch64-linux-gnu:$PWD/root/lib/aarch64-linux-gnu
ln -s ~/.cache/ms-playwright/chromium-*/chrome-linux-arm64/chrome /tmp/bin/chromium
export PATH=/tmp/bin:$PATH                        # qa_render finds a browser by shutil.which
```

**Result: `CLEAN qa_render — 5 targets rendered; not blank, legible, accent present`.** Recorded as a recipe rather than a triumph: the download is ~115 MB plus ~3 MB of unpacked libraries and it does not survive the session, so a future desktop run that needs pixels pays this cost again. It is written down so it is paid once in minutes rather than once in an hour.

## 3. P1 to the Web Developer — `qa_sources_alive` is silent until it is finished, and today it never finished

`python3 agents/tools/qa_sources_alive.py --held-only --sample 0` was started at the top of the run and **was still running forty minutes later with zero bytes of output and no JSON written.** It was killed rather than waited on further.

Two properties compose into this, both readable in the source:

1. **`TIMEOUT = 20`, applied per URL, sequentially** — and four of the held set's URLs sit on `parliament.gov.zm`, which refuses connections (§4). A connect timeout also does not bound a slow or stalled *read*.
2. **Every `print` in the program is after the loop.** There is no per-URL progress line. A run that has probed twenty-seven of twenty-eight URLs and a run that has probed none are, from the outside, the same run.

**Why this is a P1 and not a curiosity.** The Edition 05 status memo instructs, in writing: *"Re-run `qa_sources_alive.py --held-only --sample 0` immediately before the flip commit."* That makes an unbounded, un-observable step the **last** thing standing between the wave and the origin, on the day when the operation is least able to absorb a surprise. An instrument whose progress cannot be observed is the observability sibling of #52 — #52 says *print the input*; this says **print as you go, because a check that reports only at the end reports nothing at all when it does not reach the end.**

**Asked for, not implemented here** (this is the Web Developer's file and a daily run should not redesign an instrument at 11am): a per-URL line flushed as each probe returns, carrying the URL and its signature; a **bounded total budget** with an explicit partial verdict rather than an open-ended walk; and a `--skip-host` or cached-disposition path for a host already dispositioned as refusing, so four known-refusing URLs do not cost the sweep its whole budget on every run.

**What this run did instead, and it is not a substitute:** the two probe obligations the ledger actually names were run **directly and individually** with explicit budgets — which answered both questions in under two minutes and is recorded in `agents/growth/2026-09-16-held-set-source-reprobe.md`. The *tool's* full-corpus verdict is **owed and not delivered today**, and it is named here rather than quietly dropped.
