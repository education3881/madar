## The instrument broke while being used, and it was caught because it was being used

Item 165 asked whether a coverage gate is satisfied by a row saying `not yet asked`. The obvious response
was to spend the budget and ask. **`qa_claim_registers --emit` was run, and it destroyed four rows.**

Four registers that read `archived: true` with a `200` on 2026-10-21 came back `archived: false / no
snapshot` dated today — on `bqa.gov.bh`, `cgdev.org`, `ed.gov` and `elmostrador.cl`, between them the
spine of four published pairs. **Every one of those pages has many snapshots.** The CDX index returns five
for the BQA page in two seconds.

**What actually happened:** the Wayback availability endpoint answers **HTTP 200** and reports its own
failure *in the body* —

```
{"url": "...", "archived_snapshots": {}, "error": {"code": "timeout",
 "message": "client timeout at 5.0 seconds"}}
```

`archive_state()` read the empty `archived_snapshots` and returned `archived: False, "no snapshot"`.

**The protection against exactly this already existed and the defect walked around it.** The emit loop
treats `archive-unknown` as untouchable — `rows.setdefault(url, row)`, with the comment *"an outage
overwrites nothing"* — but that bucket is reached only from `archived: None`, which is produced only by a
transport *exception*. A 200 carrying an error is not an exception, so it was classified a definite
negative, and **a definite negative overwrites.** The guard was right and the classifier routed around it.

**This is #111's own sentence arriving in a new costume.** That ruling says a row reading `archive-unknown`
because we were throttled *"is an observation about us, not about the world"*, and the emit was given a
request budget because of it. **A timeout is the same event wearing a 200** — and it is worse than a wrong
row, because it overwrites a positive observation that cost a request to make. The register is this
operation's memory of whether its own citations can be re-opened, and it forgot four things because an
endpoint was slow.

**Fixed, proved and restored in this run.** `archive_state()` now returns `archived: None` with the
archive's own error code whenever the payload carries an `error` key, which routes it into the
never-overwrite bucket. Proved four ways: **two controls** — a payload with a real snapshot still returns
`True`, and a *clean* empty answer with no error still returns `False`, because "nothing is archived" is a
real answer when the API actually answered — and **two bites**, the literal 200-plus-timeout body and an
error with no snapshots key at all, both of which now return `None`. The four destroyed rows were restored
from their last good observation; the register is back to 297 archived / 73 no-snapshot / 11 never-asked and
`--check` is CLEAN.

*The budget was the right instinct aimed one layer too shallow: it rate-limits what we ask and says nothing
about how we read the answer. **An instrument that treats a refusal as data will record the world as
smaller every time it is unlucky** — and this one trends in a single direction, because a timeout can only
ever turn a `true` into a `false`, never the reverse.*

Raised as standing-queue item **167**, not because the code is still wrong but because the register now
holds a **known error with an unknown size**: this emit overwrote four rows and was caught; the emits of
2026-10-21 and earlier ran the same code with no one watching, and nothing has ever read a row back to its
source to find out. That is the forward question below, and today supplied its motive rather than its answer.
