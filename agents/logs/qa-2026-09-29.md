### Three defects in my own instrument, found and fixed before it shipped

Recorded because three in one tool is a pattern, and because the 09-28 run reported the same thing.

1. **The tool counted the README's *historical* quotation of a superseded number as a live claim.**
   The README deliberately records what the patch *used to* assert, because the staleness is the
   finding — and the first draft flagged the record for being an accurate record. That is the
   2026-09-14 masking trap inside the instrument written to catch it. Fixed with a `~~` exemption
   that honours the house convention for superseded prose and **prints every exemption**, so an
   exemption can never hide a live claim. Tense deliberately not parsed: a marker a writer sets is
   legible; a guess about *had been* versus *has* fails silently.
2. **The silent-pass guard was wrong in principle.** Copied from `qa_census` — *a census that
   cannot find the numbers it exists to compare has failed, not passed* — it failed the tree **for
   passing**, within one run, because ruling #75 makes zero claims the *goal*. **Limb: a check
   whose population can legitimately be empty cannot use "found nothing" as its failure signal; it
   needs a fixture.** Replaced with nine fixtures of sentences this queue has really carried, run
   before any tree is judged.
3. **A lookbehind fixed one wrong read and invited another.** `22 of 25 gating` yielded `gating=25`
   — the total read as the ratio. Adding `(?<!of )` made the engine start one character later and
   yield `gating=5`. Both produced a correct failure with a wrong reason inside it. **Limb: a
   negative lookbehind constrains one starting position, not the match — anchor the token.** The
   fixture caught this in the same edit that added it, which is precisely why it exists.

**And the 09-28 tokenizer scar reproduced itself on me within the hour.** Establishing ground truth,
I wrote `qa_[a-z_]+` and got **11** build steps instead of 12, because that class cannot match
`qa_a11y_lang`. Same character class, same wrong direction, one day later, independently. It is now
an assertion inside the tool: if the derived build-step set does not contain `qa_a11y_lang`, the
tool fails rather than reporting a number.
