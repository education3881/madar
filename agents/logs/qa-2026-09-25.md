## 1. The 09-24 forward question, tested before anything new was added

**Named surface:** *which of our checks has an answer that is not a function of the thing it claims
to measure?* **The probe:** run each of the 24 standing assertions **twice** against an unchanged
artefact and compare the two outputs byte for byte.

**Result: 21 of 21 locally-run assertions identical — stdout, stderr and exit code.** The `dist`
SHA-256 was taken before the first run and after the last and is unchanged (`fc57f48cfe42c4eb…`),
so the artefact really was constant. The three origin-facing tools were run separately and are
*about* the origin by design (below).

**The probe was proved before its result was believed (#35).**

| Scratch tool | Axis | Probe says |
|---|---|---|
| prints a constant | control | **SAME** ✔ |
| `datetime.now()` | fine clock | **DIFFER** ✔ (13 ms apart) |
| prints a `set` in iteration order | hash seed | **DIFFER** ✔ |
| identical stdout, exit code 0 or 1 | verdict only | **DIFFER** ✔ |
| `date.today()` | **coarse clock** | **SAME** ✘ — **the probe's own blind spot, proved not assumed** |

Hash randomisation confirmed live and varying between runs (`sys.flags.hash_randomization = 1`,
three different hashes for `"zambia"`), so the set-iteration axis was genuinely exercised. **No
assertion prints a set in iteration order.**

**The blind spot is the finding's other half.** Two runs a second apart cannot see a clock read at
day resolution. **The probe's resolution is the interval between its two runs**, so the rest was
closed **statically** — all 24 tools read for clocks, locales, network reads and enumeration order.

### What the static half found — one defect, in an instrument, not in the publication

**`qa_dist_input` rendered its timestamps through `time.localtime`.** The same artefact printed:

```
TZ=UTC         newest source 2026-09-25 09:38:48
TZ=Asia/Dubai  newest source 2026-09-25 13:38:48
```

**Its verdict never depended on it** — the staleness comparison is `d_m < s_m` on raw mtimes and is
timezone-free. Its **record** did, and the record goes into this log, which every future run reads
as true. That is **ruling #60's defect surviving inside an instrument, three days after #60 closed
it in the publication.**

**Fixed to UTC with an explicit `Z`. Proved both ways:**
- **Control** — same artefact under `TZ=UTC`, `TZ=Asia/Dubai`, `TZ=America/Los_Angeles`: **byte
  identical**, `CLEAN`, rc 0.
- **Bite** — a source file's mtime pushed ahead of `dist`: **rc 1**, `FAIL — the build is OLDER
  than its own inputs by 10.3 hour(s)`, and the two stale-path stamps — which print through the
  *same* function and would have been the easy thing to forget — **also identical across
  timezones**. Mtime restored exactly; `git status` shows only the tool file.

### Two further candidates traced, both CLEARED — recorded because "we looked" outranks "it was fine"

- **`qa_held_assets`** builds sets from an unsorted `os.listdir` and **sorts every one before
  printing**. Clean.
- **`qa_stable_order`** reads its expectations in `os.listdir` order, and sorts facets on
  `(-count, collation_key(key), key)` — a **total** order, so no tie ever falls back to enumeration
  order. Worth the line: this is the assertion whose whole subject is that no list may depend on
  filesystem enumeration order, and it does not commit its own offence.
- **`qa_sources_alive`** samples with `random.Random(args.seed)` — seeded, reproducible. The right
  pattern, and the only tool that already had it.

**Filed as ruling #65.**

## 5. Forward question for the next run, per the 08-23 rule

**Named surface: a check we own is proved against a defect we injected, and every injection so far
has been written by the same hand that wrote the check.**

#35 requires a control and a bite. Today's probe went one better and proved the *bite* four ways.
But every bite this operation has ever run was **composed by the run that wrote the assertion**,
against the defect that run was already thinking about. That is the strongest possible test of *the
defect we imagined* and no test at all of *the defect class*. The tell is already in the record:
`qa_feed_validators`' fanout control **failed on its first run** (09-24) and `qa_geo_fields`' first
bite **did not bite** (09-14) — both caught, both by luck of a careful hour, neither by a method.

**The probe, and it is cheap:** take the **real, historical** defects this operation has already
found and fixed — the 49% / 49.3% Brazil caption (90 days), the *ten years* grid tile (121 days),
the SVG `og:image` (83 days), the `/rss.xml` 404 (83 days), the 471 mis-`lang`ged chrome strings,
the 228 dangling JSON-LD references — **re-inject each one into today's `dist` and confirm the
assertion that now exists for it still fails.** Not the bite that was written for it: the defect as
it actually shipped. A check written against a remembered defect and a check that catches the
defect are two different objects, and we have never once compared them.
