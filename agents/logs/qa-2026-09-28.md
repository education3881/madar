### The oracle, and why it is not an attribute read

The bet specified the resolved value in headless Chrome, never our own markup. Reading our markup would
have been worse than useless here — see §2. The check that was built asks the **reader's** question:

> A subscriber's reader drops our field into *its* document, whose base direction is the subscriber's UI
> language and is never ours. So the property to assert is not *is this field RTL* — it is **does this
> field render the same way regardless of the base direction of the document it lands in?**

Each field is rendered twice — once inside `dir="ltr"`, once inside `dir="rtl"`, both with **no site CSS
at all** — and the *visual order* of its own characters is compared, taken from
`Range.getBoundingClientRect()` per character and reduced to a signature: one symbol per adjacent pair,
`-` if the next character sits left of its predecessor, `+` if right, `0` within half a pixel. Comparing
signatures rather than absolute positions makes the oracle immune to where the browser placed the line,
and ties resolve identically on both sides rather than flipping.

Same shape as assertion 18 (`qa_arabic_joining`): compare the artefact against **itself** under a known
transformation, so the control is a construction and not a defect we must arrange to exist.

## 2. WHAT THE MEASUREMENT FALSIFIED — ruling #73

`web/src/lib/feed.ts` has said this since 2026-08-23, not as a plan but as a mechanism:

> *"The only available lever is to prefix the value with U+200F, **which sets the paragraph base
> direction to RTL**."*

It does not. **U+200F RLM is a strong directional *character*.** It satisfies the **first-strong
heuristic** — what `dir="auto"` consults — and does nothing to a paragraph whose direction is already
determined, which is the only case a reader ever presents. Measured inside an LTR host: **identical
layout to the pixel**, first character x=258 and trailing stop x=269 with and without it. The lever is an
**isolate**, U+2066/U+2067 … U+2069; measured, the stop moves to x=8, the left edge.

**A metadata lever is verified at the layer that consumes it, never from the spec's vocabulary.** The
sentence was true of RLM in a narrow context and false about the case the comment was written for, and an
assertion that read the RLM out of our own XML would have reported the feed correct for another 36 days.

Two further defects fell out of the same measurement, and both are enumeration failures in our own code:
the channel's `title` and `description` went through **neither** helper from the day the feeds shipped —
*a helper's scope is where it is called* — and `feedDescription` was gated on `language === 'ar'`, so the
English half could not be seen by a helper that existed to fix exactly it.

**Fix (Web Developer's lane; the Assertions Engineer proved the defect and handed it over, per the
09-27 split):** isolates on every plain-text field in both languages, a `dir`/`lang` wrapper on
descriptions in both languages, and both channel fields routed through the helpers. The split cannot be
structurally enforced inside one identity, and the substance was preserved the only way available — the
check was proved against **the live historical defect** before any fix existed, so it cannot have been
shaped to pass one.

## THE NAMED FORWARD QUESTION FOR TOMORROW

Today's sweep measured, for the first time, an artefact **as a consumer we do not own would render it** —
and it found 43 defects in the one surface where that question had never been asked. The surface it still
cannot see is the one next door, and §4 says where to look.

**Every check this operation owns reads an artefact that a machine produced. Not one reads the artefacts
a human hand will apply.** Named on 09-27 and still true: the patch queue at `agents/patches/` holds
staged diffs for a hand this identity does not have, they are prose about counts that moved four times
this week, and **three of the four counts they concern moved again today.** `git apply --check` proves a
patch *applies*; nothing proves what it would then *assert*. The instrument is cheap and specific: apply
each open patch to a scratch tree, build it, and run the counts the patch claims against the counts the
tree actually has. A patch that would write `22 of 25` into `astro-pages.yml` today is a defect with a
delay fuse, and the identity that lights it cannot put it out.

**And the sharper one, from §4, because three instances in one run is a pattern and not an accident:**
every enumeration failure today was in an instrument written in the same hour it was used — a tokenizer,
an injection, a character class. **Nothing checks the checks' own bucket sets.** The cheapest probe
available: for each assertion, ask what population it *claims* to enumerate, derive that population a
second way, and compare. `qa_census` does exactly this for 14 instruments and it is the reason today's
counts could be trusted at all — so the question is not *should we build it*, it is **which of the 26 are
still outside the census, and why.** Twelve are.
