## 2. The head: standing assertion 29 — `qa_served_manifest` (ruling #89)

### What was actually wrong, stated as an invariant rather than as a gap

`<lastmod>` is a claim relating **two** quantities: a date, and a change in a page's served bytes. The
date is derived from **git history**. The bytes live in the **artefact**. The *previous* deploy's bytes
live only at the origin, until the next deploy overwrites them — **so no single place has ever held both
sides of the claim.** That does not make it unchecked. It makes it **unfalsifiable**, which is quieter:
an unchecked claim has a gap someone can name, an unfalsifiable one reads as settled.

`qa_lastmod` bounds the date from **above** (no value newer than its per-URL ceiling) and that is a good
check — it closed `9886987` and `642fef2`. But a ceiling is one-sided by construction, and **nothing has
ever bounded the other direction**, which is the one a crawler acts on.

`verify` cannot bound it either, and the reason is structural rather than configurational: **verify
compares the artifact it just published against the origin, so origin == artifact by construction.** It
answers *did my deploy land*. The question here is *across* deploys.

### The hole is reachable by editing one file. Measured, not argued.

Two probes on the real tree, each confirmed to have changed the artefact **before** the measurement was
believed (#74), each reverted in the same run.

| probe | pages whose served bytes changed | pages whose rendered **content** changed | `lastmod` moved |
|---|---|---|---|
| `web/src/styles/global.css`, one character | **120 of 121** | 0 | **0** |
| `design-assets/wordmark/madar-wordmark.svg`, one `<title>` | 117 | **117 of 120** | **0** |

The stylesheet case is a **declared** exclusion with a written reason. The wordmark case is an
**omission**, and it is worse in three ways: the file is inlined into the page by **three** build-time
`readFileSync` readers (`SiteHeader.astro`, `pages/index.astro`, `pages/ar/index.astro`); `design-assets/`
is in **neither** `CHROME_GLOBS` **nor** `CONTENT_DIRS`; and it is not in the resolver's git query at all,
which asks only for `:/web/src` and `:/web/public`. **The Designer's own working file changes what 117
served pages say and tells every crawler that nothing anywhere changed.**

*(A fourth finding fell out of probe 1's first attempt and is worth keeping: adding a **comment** to
`global.css` changed nothing at all, because Astro minifies the CSS and the content hash is computed
after. The build was right and my first probe was a no-op — which is #74 catching me rather than me
applying it.)*

### The design: two hashes, and that is the whole thing

- `bytes_sha` — the served bytes as a reader receives them.
- `content_sha` — the same bytes with the build's own `_astro` content-hashed filenames collapsed.

**Raw 120 differ, normalised 0 differ** on probe 1. So presentation-only is *mechanically* separable from
rendered-content, which is what makes this an assertion rather than an alarm. Three states that were
indistinguishable yesterday because all three were invisible:

1. `content_sha` moved, date did not → **FAIL**. No declared exception exists.
2. `bytes_sha` moved, `content_sha` did not, date did not → **reported, counted.** The resolver's own
   exclusion. The tool asserts the resolver's stated intent; it does not overrule it.
3. date moved, `content_sha` did not → **reported, counted.** The 09-04 shape, ruled a design question.
   **It has been named twelve times and has never once carried a number. It does now.**

## 7. And the surface today's sweep cannot structurally see

Today built the operation's first instrument whose memory is a **published byte**, and the seed for that
memory was taken from the origin. **Nothing anywhere verifies that the manifest the origin serves
describes the bytes the origin serves.** The emit half reads `dist`; the check half reads the origin's
manifest and compares it to a *local build*; and the one comparison never made is **the origin's manifest
against the origin's own pages.** A manifest that rode along with a deploy but described a different
tree would be a baseline that silently rebases every subsequent answer, and every exit code would read
clean while doing it — the 08-16 silent-pass trap with a cryptographic hash in front of it.

The general form, and it is sharper than the instance: **we have just made a check whose oracle is a file
we publish, and a published oracle is an artefact like any other — so what checks it?** Every instrument
before today compared a derived claim against something external. This one compares a derived claim
against *our own earlier claim*. **Which is the shape of the ruling-register drift, in code:** a number
reconciled against yesterday's number agrees with itself forever (#57), and a manifest compared only to
the next build does exactly that. *The cheap version costs four fetches — sample the origin's pages, hash
them, and assert they match what the origin's own manifest says about them. It is the self-audit the seed
mode already performs once and the check mode never performs at all.*
