Measured today on the built corpus and on the live origin:

```

**`dateModified` was already wired to `lastmodFor`** in both article templates
(`web/src/pages/articles/[...slug].astro:99`, `ar/articles/[...slug].astro:92`), so when item 96 pointed
that resolver at `agents/stats/served-dates.json` on 2026-11-11, **it moved the JSON-LD date in the same

**What remains is real, and it is a hazard rather than a defect.** The operand is still self-referential,
and the proof is on the artefact rather than in an argument:

```

  content_sha before ..  4b0a6ca8da04aa87

So **the register's own write changes the input the register reads.** Today the system sits at a fixed

## FORWARD QUESTION — what today's sweep cannot structurally see

is taken — so the board cannot tell a row that is still true from a row something else already fixed.**

because the commit that raised it closed it. That was found by one run choosing to re-measure before
taking the head; it is not a property of anything. **The ask: over the 56 rows now on the board, how many
carry a count that no longer holds — and is there a cheap, mechanical re-measure for any class of them?**
First cut needs no new instrument: every row whose evidence cell names a number and a tool is a row whose
tool can be re-run. That is #57 — *count against the population, never against yesterday's number* —
pointed at the board that quotes #57 at the top of its own file.
