## Items 116 and 119 — one rule answers both, in opposite directions, and neither answer is a matter of taste

### What the two rows asked

Item 116: the English home page spends **86,608 bytes** on a Newsreader `latin-ext` file that paints
**one** character, and JetBrains Mono spends **11,624** more on the same letter — **98,232 bytes for

Item 119: one `ɔ` on `ar/articles/2026-05-25-bo-teacher-chalk` costs **10,532 bytes**, *and it is the
same judgment one glyph over.*

Both rows handed the operation a question of taste. **It is not one.** The question has a mechanical
answer, and the two rows get opposite answers from it.

### The rule, derived from our own bundle rather than from a preference

Every family in `web/public/fonts/madar-fonts.css` ships a `latin` cut and a `latin-ext` cut, and the
`latin` cut's `unicode-range` **explicitly lists U+0304, U+0308 and U+0329** — three combining marks —
beside `U+0000-00FF`. `latin-ext` is declared **before** `latin`, so for a code point both claim the
later rule wins and the glyph comes from the file the page already has. So:

> **A one-character `latin-ext` fetch is a DEFECT when the character has a canonical decomposition every
> piece of which is inside the `latin` cut, and a PRICE when it does not.** The test is three lines of
> `unicodedata` against a range read off our own stylesheet. No one has to have an opinion.

Run against the characters this corpus actually paints:

| char | | verdict |
|---|---|---|
| `ā` U+0101 | → U+0061 U+0304, both in `latin` | **DEFECT — repair it** |
| `Ā` U+0100 | → U+0041 U+0304, both in `latin` | **DEFECT — repair it** |
| `ɔ` U+0254 | atomic, no decomposition exists | **PRICE** |
| `ʿ` U+02BF | atomic | **PRICE** |
| `ṣ` U+1E63 | → U+0073 U+0323, and U+0323 is **not** in `latin` | **PRICE** |
| `ḥ` U+1E25 | → U+0068 U+0323, same | **PRICE** |

**Item 116 is a defect. Item 119 is a price.** The difference is not that one glyph matters more than the
other; it is that one has an equivalent the page can already paint and the other does not.
