# A classifier's kernel is a denominator, and an empty kernel is not a closed one

walked into on the first instrument it touched. Family: **assertion discipline** (#16, #35, #36, #37,

**It answers the 2026-11-03 forward question verbatim**, which asked: *which NON-render assertion's

## The ruling

**A CLASSIFIER'S KERNEL IS A DENOMINATOR.** #126 established that every ruler is a projection and
every projection has a kernel — a set of distinct states it maps to one output. A **classifier's**
kernel has a property the others do not: its outputs are the **buckets other instruments count**, so
two states collapsed into one bucket are not merely indistinguishable, they are **added together** and
then reported as a rate. The kernel does not hide a defect; it **manufactures a figure**.

**AND AN EMPTY KERNEL IS NOT A CLOSED ONE.** #126 clause 2 says a kernel is closed by changing the
ruler or by constructing the geometry in which it is empty. Those two are not equivalent, and the
difference is **who guarantees the emptiness**. A kernel that is empty *by construction* — like
`qa_feed_direction`'s, where the probe pins `white-space: pre` and a 60,000 px box so a wrap cannot
occur — stays empty whatever the corpus does. A kernel that is empty *because nothing has yet landed
in it* is a property of today's population, and **the population is what the operation changes every
time it publishes.** A check whose kernel is empty by accident is a check that is correct until the
next piece ships.

**Binding, in three clauses.**

1. **A classifier states its buckets' kernel in the same sentence as its ruler** (#126 clause 1
   extended from a ruler to a bucket set), and it states whether the kernel is empty **by construction
   or by population count**. The two words are not interchangeable and only one of them is a closure.
2. **A kernel empty by population carries the count and the date it was taken** — *0 of 353 on
   2026-11-04* — because that is the number that will stop being zero, and a reader who finds
   `0 instances` with no date cannot tell a guarantee from a measurement.
3. **Where the next artefact in the pipeline is known to occupy the kernel, the ruler changes before
   that artefact ships, not after.** A ruler changed after the first instance arrives is a correction
   and prices the instance; changed before, it costs one state and no figure was ever wrong.

## What was measured, and where

`qa_claim_registers.classify()` (#111, standing assertion 35) answers *can the evidence under a
published claim still be opened, and by whom?* Its ruler is two bits about two hosts — **does a
snapshot exist**, and **does the origin answer us** — and the five states it projects them onto are
the four rows of its own header plus `archive-unknown`. Today's content function asked it about the
Bahrain draft's five registers, by importing its own functions rather than reimplementing them:

| Register | `classify()` | What is actually true |
|---|---|---|
| `data.gov.bh` dataset — 23 of the piece's figures | `live-only` | one hosting decision from gone |
| `bqa.gov.bh` Annual Report 2025 PDF — the Gold Seals and a verbatim quotation | `live-only` | one hosting decision from gone |
| `bqa.gov.bh` Performance Report 24-25 PDF | `archived` 2026-07-17 | in the public record |
| `bqa.gov.bh/open-data/` | `archived` 2026-01-18 | in the public record |
| **our own `2026-05-26-bahrain-bqa-public-grades` page** | **`live-only`** | **in public git history, permanently, whatever any archive holds** |

Three of five hold no snapshot, and **one of those three is ours.** `live-only` is not a neutral label:
it is the state the tool's own claim-level join prices as single-copy risk, and it is the state behind
the one figure #111 is quoted for — *of 342 cited registers, 40 exist in exactly one copy.* A claim
resting on our own served bytes has a second copy **by construction**: the repository is public, the
article's source file is in it, and anybody can re-open the quotation from git history without asking
archive.org or us for anything. The ruler cannot say so, because **whose host it is** was never one of
its two bits.

### The emptiness, and the date on it

`qa_claim_registers.json` holds **353 cited registers on 2026-11-04 and 0 of them are ours.** So the
kernel has never held an instance, every number #111 has ever reported is unaffected, and **there is no
step discontinuity to reconcile backward** — which is worth saying only because the 2026-10-04 second
amendment's limb 2 is the opposite case and the usual one. The arithmetic was not wrong. The arithmetic
was never asked.

**It stops being empty at the next flip.** The Bahrain draft cites our own predecessor page for the
closing question it quotes verbatim — the first time this publication has cited itself as a register —
and on the day that flag moves, that row arrives as the **fiftieth `live-only`** and is counted in the
single-copy figure. Nothing would have caught it. `qa_claim_registers --check` asserts only that every
cited register **has a dated row**, and the row would have been there, correct in both its bits and
wrong in its bucket.

## The action of record, and why it is one line rather than a tool

`classify()` gains a fifth state, **`ours-git-archived`**, tested before the archive question because
it does not depend on the answer: whatever a snapshot holds, we hold it too, in public. The ruler is
changed **before** the instance arrives, per clause 3.

Proved seven ways on the classifier directly, two of which are the pair that matters — a `data.gov.bh`
URL with `archived: False, origin: 200` still reads `live-only`, and our own page with the identical
two bits now reads `ours-git-archived` — and the three pre-existing states (`archived`,
`walled-no-snapshot`, `GONE`, `archive-unknown`) unchanged. The gated `--check` half re-run on the real
register returns the identical population it returned this morning: **archived 289 · live-only 49 ·
walled-no-snapshot 14 · GONE 1, 353 registers, CLEAN.** *A ruler change that moves no current number is
the only kind that can be made without restating a published figure* — and it is available exactly
once per kernel, in the window before the first instance.

## AMENDED THE SAME DAY, BY THE GROWTH FUNCTION, AND THE AMENDMENT IS THE STRONGER HALF

The ruling above was filed with the kernel **empty by population count** — *0 of 353, and the next flip
occupies it.* Two hours later the growth function went to execute issue #12's default over the 23 named
registers, derived the set from the register as it stood on the issue's own date rather than from
memory, and **two of the twenty-three are `web.archive.org/web/…` URLs** — cited in the first place
*because the owner's copy had already gone*.

They score **`live-only`**. The availability API is asked *is there a snapshot of this URL* and answers
no, **correctly**: there is no snapshot of a snapshot. So the two rows in the entire register that are
archived **by construction** are filed under the one state the claim-level join prices as single-copy
risk. **2 of 342 on 2026-10-24 and 2 of 354 today**, unchanged in between.

Three things follow, and they change the ruling rather than illustrating it.

1. **Clause 1's two words were not enough.** A kernel is empty by construction, empty by population
   count, or **not empty at all and never looked at**. The third is the dangerous one precisely because
   it produces no symptom: the bucket counts, the rate publishes, nothing contradicts it. The first
   instance found today was the harmless kind and the second was this one, in the same classifier,
   found by *using* it twice in one day for two different purposes.
2. **It restates a published figure, and the earlier sentence in this ruling must not stand
   unqualified.** #111 is quoted for *of 342 cited registers, 40 exist in exactly one copy* — the
   correct figure for that population was **38**. Today's 49 `live-only` is **47**. The re-derivation
   was run over the stored register with **no network call and no `observed` date touched**, because
   the state is a pure function of two bits that were already on file: 2 rows moved, `archived 290 ·
   live-only 47 · walled-no-snapshot 14 · cited-as-archive 2 · GONE 1`. *A classifier's kernel is a
   denominator* was the claim; here is the numerator it was hiding.
3. **A second state, `cited-as-archive`.** Tested before everything else, for the same reason
   `ours-git-archived` is: it does not depend on the archive's answer about the URL, only on what the
   URL is. Proved five ways beside the first state, controls on the three pre-existing buckets.

**And the method is the part to carry.** Neither instance was found by auditing the instrument. The
first came from the content function asking it about five registers; the second from the growth function
asking it which registers were authorised for submission. **Two kernels in one classifier in one day,
both found by using it for something else** — which is the inverse of 2026-11-03's conclusion that *the
rate is a property of the reader*. It is also a property of how many different questions the instrument
is asked.

## What this does NOT claim

**It does not say a self-citation is safe.** It says the *risk is of a different kind*: not "the
register may vanish from the public record" but "the operation may edit its own past", which is
`qa_citation_identity` (#112) and git's job, not an archive's. The new state is a statement about
**where the second copy is**, not a statement that nothing can go wrong.

**And it does not close #126's question for the other three projection kinds.** Yesterday named a
count, a set and a bucket set. Today answered a **classifier**, which is a fourth kind nobody had
listed — found, as every one of these has been, by using the instrument rather than by auditing it.
